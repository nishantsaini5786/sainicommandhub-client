tcpdump is a command-line packet analyzer. It captures packets from network interfaces or reads saved PCAP/PCAPNG files, then prints packets matching a Boolean filter expression. It is especially useful for troubleshooting, protocol learning, incident-response evidence collection and validating what is actually crossing an interface.

What is tcpdump? (Deep Theory)

tcpdump sits close to the packet-capture layer. Instead of behaving like a vulnerability scanner, it observes traffic that the host can capture and applies a Berkeley Packet Filter (BPF) expression before processing matching packets.

Core Concepts

  • Interface: the network device from which packets are captured, such as wlan0, eth0 or Linux any.
  • Capture filter: an expression such as tcp port 443 that limits packets processed by tcpdump.
  • PCAP: a packet-capture file that can be saved with -w and later analyzed with -r or Wireshark.
  • Snaplen: the number of bytes captured from each packet; -s 0 requests the full packet under current tcpdump behavior.
  • Promiscuous mode: an interface capture mode that can expose more link-layer traffic when supported; it is not the same as monitor mode.
  • Filter primitives: host, net, port, src, dst and protocol selectors can be combined with and, or and not.

Mental Model

INTERFACE → CAPTURE FILTER → PACKET BUFFER → DECODE / PRINT OR PCAP → ANALYSIS

💡
Important: tcpdump observes packets available to the capture mechanism. It does not automatically see every packet on a switched network, and encrypted application payloads remain encrypted unless you have an appropriate authorized decryption context.
Installation & First Checks

Install on Kali / Debian

sudo apt update && sudo apt install tcpdump

Verify

tcpdump --version
sudo tcpdump -D

Live interface capture commonly requires elevated privileges. Reading an existing capture file generally does not require the same capture privileges. Exact interface names and supported features vary by operating system and libpcap build.

BPF Filter Thinking

The filter expression is one of tcpdump's most important skills. Build filters from small primitives, test them, then combine them.

PrimitiveMeaningExample
hostEither source or destination hosthost 192.168.1.10
src hostSource host onlysrc host 192.168.1.10
dst hostDestination host onlydst host 192.168.1.10
netNetwork/CIDRnet 192.168.1.0/24
portSource or destination portport 443
tcp / udp / icmp / arpProtocol selectortcp
andBoth conditionstcp and port 443
orEither conditionport 80 or port 443
notExclude conditionip and not port 22
🧠
When shell metacharacters such as & are present in a filter, quote the expression so the shell does not interpret it. Using -- before the expression is also a documented best-practice pattern.

Recommended lab sequence

  1. Run sudo tcpdump -D and identify the interface carrying your lab traffic.
  2. Begin with -nn to avoid name-resolution noise.
  3. Use a narrow filter such as host 192.168.1.10 or tcp port 443.
  4. For evidence, write a PCAP with -s 0 -w capture.pcap.
  5. Stop with -c when possible to keep captures manageable.
  6. Analyze offline with tcpdump -r and, where appropriate, Wireshark.

Troubleshooting

Permission denied

Live capture may require root or appropriate packet-capture capabilities. Test with sudo tcpdump -D and follow your system's privilege model.

No packets appear

  • Confirm the correct interface with tcpdump -D.
  • Generate known traffic from the authorized lab host.
  • Temporarily remove a narrow filter and verify that the interface sees traffic.
  • Check whether the traffic is actually routed through that interface.

Packets are dropped

High traffic rates can overwhelm capture buffers. Consider a narrower BPF filter, a suitable -B buffer size, and an appropriate snapshot length. tcpdump reports capture/drop counters when the capture ends.

PCAP is huge

Use a precise filter, -c, -C/-G rotation, or a shorter capture window. Avoid collecting traffic you do not need.

tcpdump vs Wireshark vs tshark
ToolStrengthBest learning use
tcpdumpFast CLI capture/filteringLearn BPF and packet flow
WiresharkDeep graphical protocol analysisInspect complex conversations
tsharkCLI protocol dissectionAutomation and structured extraction

A strong workflow is tcpdump → PCAP → Wireshark/tshark → logs. tcpdump is excellent for getting a focused capture quickly; it is not a replacement for every higher-level protocol-analysis tool.
