Amass is the industry-standard tool for attack surface mapping and external asset discovery. Created by Jeff Foley (OWASP project), Amass uses dozens of data sources to discover subdomains, IP addresses, ASNs, and network relationships. If you're doing bug bounty or red team recon, Amass is your first tool.

What is Amass? (Deep Theory)

Imagine you're a hacker targeting a company. Before you attack, you need to know: what servers do they have? What subdomains? What IPs? What services are exposed? This is called attack surface mapping.

Amass does this automatically. It queries dozens of sources — DNS servers, certificate transparency logs, WHOIS databases, search engines, public APIs — and pieces together a map of a company's entire internet-facing infrastructure.

What Does Amass Actually Discover?

  • Subdomains — Like mail.example.com, api.example.com, dev.example.com
  • IP Addresses — All IPs associated with the target's domains
  • ASNs — Autonomous System Numbers (network ownership)
  • Netblocks — CIDR ranges owned by the target
  • DNS Records — A, AAAA, MX, NS, TXT, SOA, CNAME, PTR
  • Certificates — SSL/TLS certs revealing hidden domains
  • WHOIS Data — Registration info, contacts
  • Relationships — Graph of how domains/IPs/ASNs connect

Passive vs Active Enumeration

Amass has two modes of operation — understanding the difference is critical:

Passive Enumeration

  • Uses only third-party data sources — never touches the target directly
  • No packets sent to target = invisible to defenders
  • Slower but safer for stealth operations
  • Sources: Certificate Transparency, VirusTotal, Shodan, SecurityTrails, etc.

Active Enumeration

  • Sends DNS queries, TCP connections, HTTP requests to the target
  • Can be detected by IDS/IPS — leaves logs
  • Faster and more accurate
  • Also does zone transfers, DNS brute-forcing, cert grabbing

Brute-Force Enumeration

  • Uses a wordlist to guess subdomains
  • Example: admin.example.com, dev.example.com, mail.example.com
  • Very loud — target's DNS server sees thousands of queries
  • Combines with passive data for best results

Basic Commands
1. Simple Subdomain Enumeration
Find all subdomains of a target using default sources.
amass enum -d example.com
www.example.com mail.example.com api.example.com dev.example.com blog.example.com
2. Save Results to File
amass enum -d example.com -o results.txt
3. Silent Mode (No Progress)
Clean output for piping to other tools.
amass enum -d example.com -silent
4. Multiple Domains
amass enum -d example.com -d example.org -d example.net
5. Domains From File
amass enum -df domains.txt
Passive Enumeration
6. Passive Only
Use only OSINT sources — no direct queries to target.
amass enum -passive -d example.com
7. List All Sources
See all available OSINT data sources.
amass enum -list
Available data sources: - Argonaut - AskSearch - Baidu - Bing - BufferOver - CertSpotter - CIRCL - Crtsh - DNSDB - ...
8. Use Specific Sources
Only use certain sources — combine whitelist or blacklist.
amass enum -d example.com -include crtsh,virustotal,shodan
9. Exclude Sources
amass enum -d example.com -exclude bing,baidu
Active Enumeration
10. Active Mode
Sends actual DNS queries + HTTPS probes to target.
amass enum -active -d example.com
11. Brute Force with Wordlist
Try words from a list as subdomains.
amass enum -brute -d example.com -w subdomains.txt
12. Combine Active + Brute
Maximum coverage — all methods together.
amass enum -active -brute -d example.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
13. DNS Resolve Found Subdomains
After enumeration, resolve IPs for each subdomain.
amass enum -d example.com -ip
www.example.com 93.184.216.34 mail.example.com 93.184.216.35 api.example.com 93.184.216.40
14. Show DNS Records
amass enum -d example.com -dns
Intelligence Gathering (amass intel)
15. Find Root Domains of Organization
Discover all domains belonging to a company.
amass intel -org "Example Inc"
example.com example.org example.net example.io
16. Enumerate ASN
Find all netblocks owned by an ASN.
amass intel -asn 12345
17. Find Domains in WHOIS Reverse
Find domains registered by an email or name.
amass intel -whois -d example.com
18. Reverse WHOIS by Email
amass intel -whois -d example.com -emails
19. CIDR Netblock Search
amass intel -cidr 192.168.0.0/16
20. Reverse DNS on IP Range
amass intel -addr 192.168.1.0/24
Advanced Features
21. Config File
Use custom config with API keys.
amass enum -d example.com -config ~/.config/amass/config.ini
22. Timeout Control
Set max time (minutes) for enumeration.
amass enum -d example.com -timeout 30
23. Increase Concurrency
Faster but noisier — more parallel queries.
amass enum -d example.com -active -max-dns-queries 500
24. Use Proxy
amass enum -d example.com -proxy socks5://127.0.0.1:9050
25. Save to Database
Persist results in Amass's local DB for tracking.
amass enum -d example.com -oA ./output -dir ./amass_db
26. View Database
amass db -show -dir ./amass_db
27. Track Changes Over Time
See what subdomains appeared since last scan.
amass track -d example.com -dir ./amass_db
28. Visualize Graph
Generate an HTML/JS visualization of attack surface.
amass viz -d3 -dir ./amass_db -o graph.html
Practical Workflows

Bug Bounty Recon Workflow

Step 1: Passive Recon First
Start with passive to avoid detection.
amass enum -passive -d target.com -o passive-subs.txt
Step 2: Active Enumeration
Now use active methods for more findings.
amass enum -active -d target.com -o active-subs.txt
Step 3: Brute Force Deep Dive
Use large wordlist for maximum coverage.
amass enum -brute -d target.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -o brute-subs.txt
Step 4: Combine All Results
cat passive-subs.txt active-subs.txt brute-subs.txt | sort -u > all-subs.txt
Step 5: Resolve IPs
Get IP addresses for all subdomains.
amass enum -d target.com -oA ./output -dir ./amass_db -ip
Step 6: Scan Live Hosts
Filter live subdomains and scan them.
cat all-subs.txt | httpx -silent | nmap -iL - -sV -T4

Troubleshooting

"No results found"

  • Domain might be behind Cloudflare/WAF — use passive mode
  • Try adding API keys to ~/.config/amass/config.ini
  • Increase timeout: -timeout 60

"Rate limit exceeded"

  • Some sources limit free queries — reduce concurrency: -max-dns-queries 100
  • Use -config with registered API keys

"Slow enumeration"

  • Use -passive for speed
  • Reduce sources: -include crtsh,virustotal
  • Set timeout: -timeout 10

"Too many false positives"

  • Use -active -ip to verify live hosts
  • Combine with httpx to filter responsive hosts

Amass uses too much memory

  • Reduce concurrency: -max-dns-queries 50
  • Delete old database: rm -rf ./amass_db
