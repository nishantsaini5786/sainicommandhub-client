Tenable Nessus is a vulnerability assessment platform used to identify security weaknesses, missing patches, insecure configurations, exposed services and other findings on authorized systems. Nessus combines a scanner engine with a large plugin library, scan policies, credentials, schedules and reporting workflows.

What is Nessus? — Deep Theory

Nessus is primarily a vulnerability scanner, not an exploitation framework. A Nessus scan evaluates a target against checks implemented through plugins and reports findings with evidence, severity information and remediation context.

Scanner → Plugin → Finding

The core mental model is:

TARGET → DISCOVERY → SERVICE DETECTION → PLUGIN CHECKS → EVIDENCE → VULNERABILITY FINDING → REMEDIATION → RESCAN

  • Target: the authorized IP address, hostname, range or asset set.
  • Discovery: Nessus determines what hosts/services are reachable within the scan configuration.
  • Plugins: individual checks implement detection logic for vulnerabilities, configuration problems and other security conditions.
  • Evidence: the scanner records information supporting a finding, such as service/version details or configuration observations.
  • Remediation: the security team fixes the underlying issue and validates the result with a follow-up scan.
💡
Important: A Nessus finding is not automatically proof that a system can be exploited. Detection quality depends on the plugin, available evidence, scan configuration, credentials and target state. Validate important findings before treating them as confirmed exploitable vulnerabilities.
Nessus Architecture & Components

Scanner Engine

The scanner performs network communication and executes the checks selected by the scan configuration. In a lab, think of it as the component that actually communicates with the target.

Plugins

Nessus plugins contain detection logic. Plugins can cover vulnerabilities, service identification, configuration issues, compliance-related checks and other security assessments.

Policies

A policy is a reusable set of scan configuration options. Tenable documents policies as controlling technical scan parameters, credentials and granular plugin/family specifications.

Credentials

Authenticated scans can provide deeper visibility because Nessus can inspect local system information when valid credentials and the correct policy configuration are supplied.

Results & Reports

Results are organized around hosts, findings, severity, plugin information and supporting evidence. The goal is not simply to produce a huge list of alerts, but to turn findings into actionable remediation work.

Installation & First Launch — Kali Linux

On Kali, Nessus is normally installed from a Tenable-provided package rather than from the default Kali repositories. Download the appropriate package from Tenable, install it using the package manager, start the service, then open the local web interface.

sudo dpkg -i ./Nessus-*.deb sudo systemctl enable --now nessusd sudo systemctl status nessusd xdg-open https://127.0.0.1:8834

Exact package names and installation steps can vary by release. After installation, complete the initial browser setup, choose the appropriate Nessus edition/license, and allow plugins to initialize/update before expecting scan results to be complete.

🔐
CLI note: Tenable's current documentation states that Nessus CLI administration commands require administrative privileges and uses /opt/nessus/sbin/nessuscli on Linux.
Basic Vulnerability-Scanning Workflow
  1. Define scope: identify only assets you own or have written permission to assess.
  2. Confirm reachability: verify the scanner can route to the authorized target network.
  3. Choose a scan template: select the template appropriate for the lab or assessment objective.
  4. Set targets: enter the approved IPs, hostnames or ranges.
  5. Configure discovery: decide how ports and services should be identified.
  6. Configure credentials: when authorized, provide SSH/Windows or other supported credentials for authenticated checks.
  7. Review plugins/policies: avoid blindly changing plugin families; understand what your scan is intended to measure.
  8. Run the scan: monitor progress and scanner health.
  9. Validate findings: inspect plugin output, affected service/version and evidence.
  10. Remediate and rescan: confirm that fixes actually removed the issue.

Important Scan Concepts

Unauthenticated vs Authenticated Scans

An unauthenticated scan evaluates what can be observed remotely. An authenticated scan can inspect additional local information using authorized credentials. Authenticated visibility can reduce uncertainty around installed software, patches and configuration.

Plugin Families

Plugins are grouped into families. A scan policy can use granular family/plugin selections. This is useful when building targeted assessments rather than running every possible check.

Severity

Nessus findings commonly use severity levels to help prioritize review. Severity is a triage signal, not a substitute for understanding business context, exploitability, exposure and compensating controls.

False Positives & False Negatives

Detection tools can make mistakes or lack sufficient evidence. Always read the plugin output and independently validate critical findings where appropriate.

Useful Nessus + Nmap Lab Workflow

Nessus and Nmap answer related but different questions. Nmap is excellent for discovering hosts, ports and services; Nessus adds a large vulnerability-checking/plugin layer.

# 1. Discover/validate services nmap -Pn -sV <LAB-IP> # 2. Open Nessus xdg-open https://127.0.0.1:8834 # 3. Create an appropriate scan in the Nessus UI # 4. Set only authorized LAB-IP targets # 5. Review findings and plugin evidence # 6. Fix the vulnerable configuration # 7. Run the scan again to verify remediation

Tip: Do not assume that every service discovered by Nmap represents a vulnerability. Use the Nessus results to investigate specific security conditions and then validate important findings.

Troubleshooting — Common Problems

1. Browser cannot open port 8834

Check the service, listener and logs:

sudo systemctl status nessusd sudo ss -lntp | grep 8834 sudo journalctl -u nessusd -n 100 --no-pager

2. Scan reports fewer services than expected

Check routing, firewall rules, target reachability, discovery settings and whether the selected scan policy is appropriate.

3. Plugin updates are incomplete

Check registration, connectivity, service logs and plugin update state. Avoid interpreting a partially initialized scanner as a complete vulnerability assessment.

4. Authenticated checks are missing

Review credential configuration, permissions, network access and the authentication requirements for the operating system being assessed.

5. Scanner is slow

Large target ranges, high plugin coverage, network latency, rate controls and target resource limits can all affect scan duration.

Learning Path — Nessus for Cybersecurity
  1. Learn TCP/IP, ports and service identification.
  2. Practice Nmap on your own vulnerable VM.
  3. Install Nessus and understand the scanner architecture.
  4. Run a basic scan against an intentionally vulnerable lab.
  5. Study plugin output instead of only looking at severity.
  6. Configure an authenticated Linux/Windows lab scan.
  7. Compare unauthenticated and authenticated results.
  8. Practice remediation and verification scans.
  9. Learn how vulnerability findings map to CVE/CVSS, affected versions and remediation guidance.
  10. Document findings like a professional vulnerability-assessment report.
