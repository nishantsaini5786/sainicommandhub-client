AIRGEDDON
Wireless Security · All-in-One Auditing Framework
Intermediate Menu-Driven Evil Twin PMKID

Airgeddon is a multi-use bash script that acts as an all-in-one wireless auditing framework[citation:1][citation:5]. Unlike Aircrack-ng where you type individual commands, Airgeddon gives you a guided menu interface that automates handshake capture, PMKID attacks, Evil Twin setups, WPS attacks, and more[citation:6][citation:12]. It's like a remote control that coordinates Aircrack-ng, Hashcat, Reaver, and other tools behind the scenes[citation:7][citation:8].

What is Airgeddon? (Deep Theory)

Imagine you're doing a wireless security audit. With Aircrack-ng, you'd type 20+ commands manually: enable monitor mode, scan, lock target, capture handshake, deauth, crack. Airgeddon does all of this through a numbered menu system — you just press numbers[citation:6][citation:16].

What Tools Does Airgeddon Use Internally?

  • Aircrack-ng — Handshake capture and cracking[citation:12]
  • MDK4 — DoS attacks (deauth floods, beacon flooding)[citation:3][citation:12]
  • Reaver — WPS PIN brute-force and Pixie Dust[citation:4][citation:12]
  • Hashcat — GPU-accelerated password cracking[citation:8]
  • Hostapd — Creating rogue access points for Evil Twin[citation:8]
  • Dnsmasq — DHCP and DNS server for fake APs[citation:12]
  • Bettercap — MITM framework[citation:12]
💡
Why it matters: Airgeddon is what penetration testers use when they want speed and automation. Instead of remembering 50 flags, you just navigate a menu. It's the "GUI version" of wireless hacking — but in your terminal.
Airgeddon Attack Modes (Full List)

When you launch Airgeddon, you get a numbered menu. Here are the main attack modes[citation:6][citation:16]:

1. DoS Attacks (Menu 5 in some versions)

Denial of Service attacks to disrupt wireless communication[citation:3]. Methods include:

  • Deauthentication Flood — Sends continuous deauth frames to disconnect all clients[citation:3]
  • Disassociation Attack — Similar to deauth but more subtle, bypasses some detection[citation:3]
  • Beacon Flooding — Broadcasts thousands of fake SSIDs to confuse devices[citation:3]
  • Probe Request Flood — Simulates many devices searching for APs[citation:3]
  • DoS Pursuit Mode — Auto-follows AP if it changes channels[citation:8]

2. Handshake / PMKID Capture (Menu 6)

Automated WPA/WPA2 handshake capture and PMKID extraction[citation:6][citation:8].

  • Handshake Capture — Auto-scan, target selection, deauth, capture, verify[citation:19]
  • PMKID Attack — Clientless attack — extracts hash directly from AP[citation:6]
  • Handshake Cleaning — Optimizes captured .cap files[citation:8]

3. Offline Decryption (Menu 7)

Crack captured handshakes using dictionary, brute-force, or rule-based attacks[citation:8].

  • Dictionary Attack — Uses wordlist (rockyou.txt)[citation:19]
  • Brute-Force Attack — Tries all combinations (slow)[citation:19]
  • Rule-Based Attack — Modifies dictionary words[citation:8]
  • GPU Support — Uses Hashcat for faster cracking[citation:8]

4. Evil Twin Attacks (Menu 8)

Most advanced feature — creates a fake access point that clones a legitimate network[citation:6][citation:10].

  • Evil Twin with Sniffing — Fake AP + traffic capture[citation:9]
  • Evil Twin with SSL Strip — Downgrades HTTPS to HTTP[citation:9]
  • Evil Twin "Only AP" — Just the fake AP, external sniffer[citation:9]
  • Black Hole Captive Portal — Fake login page to capture WiFi passwords[citation:9]
⚠️
How Evil Twin works: You create a fake AP with the same name (SSID) as a real network. When users connect, they see a fake login page (captive portal). They enter the WiFi password, which you capture. This tests user awareness and network security[citation:6][citation:10].

5. WPS Attacks (Menu 9)

Wi-Fi Protected Setup attacks[citation:4][citation:6].

  • Pixie Dust Attack — Exploits weak WPS implementations — fast[citation:4][citation:6]
  • WPS PIN Brute-Force — Tries all PINs (slow, may lock AP)[citation:4]
  • Known PIN Database — Uses database of known default PINs[citation:4]

6. Enterprise Attacks (Menu 11)

Attacks against WPA-Enterprise networks (EAP attacks)[citation:12][citation:17].

7. Other Features

  • Hidden ESSID Decloaking — Reveals hidden network names[citation:8]
  • MAC Address Spoofing — Randomize your adapter MAC[citation:6]
  • Probe Request Capture — Logs SSIDs from client devices[citation:6]
  • Multi-Instance — Run multiple Airgeddon attacks simultaneously[citation:8]

sudo apt update && sudo apt install -y airgeddon

Step-by-Step Workflow (Handshake Attack)
Step 1: Launch Airgeddon
sudo bash airgeddon.sh
Step 2: Select Interface
Airgeddon detects wireless interfaces. Select your adapter (wlan0) by pressing its number[citation:19].
Step 3: Enable Monitor Mode
Press 2 for "Put interface in monitor mode"[citation:19].
Step 4: Go to Handshake/PMKID Menu
Press 5 or 6 for handshake/PMKID tools menu[citation:19].
Step 5: Target Selection
Press 4 for target scanning. Wait for networks to appear, then press Ctrl+C to stop[citation:19].
Step 6: Capture Handshake
Press 5 to capture handshake. Choose deauth method (usually option 1). Wait for handshake capture[citation:19].
Step 7: Offline Decrypt
After capture, press 0 to go back, then 6 for offline decrypt menu. Choose 1 for dictionary attack[citation:19].
Step 8: Select Wordlist
Airgeddon prompts for wordlist. Select rockyou.txt or your custom list[citation:19].
Step 9: Wait for Crack
If password is in wordlist, it displays on screen and saves to file[citation:19].
Step 10: Cleanup
Exit Airgeddon — it cleans temp files and optionally keeps monitor mode[citation:9].

Troubleshooting

"Missing dependency" error

  • Airgeddon checks for required tools on launch[citation:12]
  • Install missing packages: sudo apt install aircrack-ng mdk4 reaver hashcat

"Script exits after selecting mode"

  • Ensure adapter is in monitor mode[citation:12]
  • Kill conflicting processes: sudo airmon-ng check kill

"No handshake captured"

  • Wait for a client to connect — or use deauth to force reconnect[citation:19]
  • Check channel — lock on target's channel
  • Move closer to target

"Evil Twin not working"

  • Some networks use client isolation[citation:10]
  • WPA3 networks harder to attack[citation:17]
  • Check iptables/nftables compatibility[citation:8]
