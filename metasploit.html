ADVANCED 50+ COMMANDS METASPLOIT FRAMEWORK

Metasploit Framework is a modular penetration-testing platform built around exploits, payloads, auxiliary modules, post modules, encoders and other components. It provides a consistent console workflow for discovering modules, inspecting their requirements, configuring options and running authorized security tests.

What is Metasploit? (Deep Theory)

Metasploit is best understood as a module-driven security framework. Instead of one giant command that performs every task, the framework contains many specialized modules. You select the module, inspect its documentation and options, configure the values required by the lab, and then run it.

Major Module Types

  • Auxiliary: supporting modules for scanning, enumeration, protocol interaction and other non-exploit tasks.
  • Exploit: modules designed to trigger a specific vulnerability or weakness on a compatible target.
  • Payload: code delivered or executed after an exploit or through another supported delivery mechanism.
  • Post: modules intended for post-compromise activities against an existing session.
  • Encoder / NOP: framework components used by certain payload and exploit workflows.

The Core Mental Model

SEARCH → USE → INFO → OPTIONS → SET → CHECK → RUN/EXPLOIT → SESSION

This workflow is more important than memorizing individual exploit names. Always read the module information and verify the target/version and required options before executing a module.

💡
Key Insight: A Metasploit module is not automatically appropriate just because its name looks relevant. Compatibility depends on the target version, service configuration, architecture, module requirements and the exact vulnerability conditions.
Installation & First Launch

Kali Linux

sudo apt update && sudo apt install -y metasploit-framework

Launch

msfconsole

Check Version From Shell

msfconsole --version

For a learning environment, a local vulnerable VM such as Metasploitable or an intentionally vulnerable CTF machine is the safest place to practice exploit-module workflows.

Auxiliary Scanner Workflow

Auxiliary modules are useful when you want Metasploit to perform enumeration without exploiting the target. Rapid7's documentation uses HTTP scanner modules as examples of this workflow.

Search
Find a scanner appropriate for the service or protocol you are testing.
Use
Load the module using its full module path.
Inspect
Run info, show options and show missing before execution.
Configure
Set RHOSTS, RPORT, THREADS or other module-specific options.
Run
Use run and review the module's output.
Record
Review hosts/services/notes in the Metasploit database when database integration is enabled.
Exploit Module Workflow

Exploit modules should be used only against a target inside your authorized scope. Rapid7 recommends using your own local test environment, such as a VM or Docker-based lab, for exploitation practice.

Identify the Service
Use your lab enumeration results to determine the service, version and relevant vulnerability.
Search the Framework
Search by product, vulnerability name, module type or CVE.
Read Info
Check module description, references, targets and prerequisites.
Inspect Options
Use show options, show missing, show targets and show payloads.
Check When Supported
If the module implements a check method, use check before attempting exploitation.
Run in the Lab
Set only the values required by the authorized lab and execute the module.
Payloads & Meterpreter

A payload is the component intended to perform an action after successful delivery. Payload names can encode platform, architecture, stage and transport. For example, Rapid7 documents the structure of staged payload names such as windows/x64/meterpreter/reverse_tcp.

Understand the Name

windows/x64/meterpreter/reverse_tcp

windows = platform · x64 = architecture · meterpreter = payload stage · reverse_tcp = communication/stager style.

Meterpreter Concept

Meterpreter is an advanced Metasploit payload with a rich command interface and extension architecture. It is commonly used in authorized post-exploitation labs for session management, information gathering and controlled demonstrations.

Basic Session Pattern

sessions sessions -i 1 background sessions -v

Database & Workspace Workflow

Metasploit can maintain structured information about hosts, services, credentials and vulnerabilities. Workspaces help keep different lab environments separated.

db_status workspace workspace -a lab01 workspace lab01 hosts services creds vulns
🗂
Good habit: Create a separate workspace for each CTF/lab. This keeps hosts, services and other collected records easier to interpret.
Resource Scripts & Repeatable Labs

Resource files let you place a repeatable sequence of console commands into a file and execute it with resource. This is useful for rebuilding a lab workflow without manually typing every command.

nano lab.rc resource lab.rc

Keep resource files free of real credentials or sensitive production targets. For training, use placeholders or isolated lab addresses.

Troubleshooting

Module Not Found

  • Run a broader search query.
  • Check the exact module path shown by the search results.
  • Update the Metasploit package if your installed module database is outdated.

Required Option Missing

  • Run show missing.
  • Read show options and info.
  • Set only the required values that belong to your authorized lab.

Exploit Does Not Work

  • Confirm the target version is actually vulnerable.
  • Read the module's target list with show targets.
  • Check whether the service is reachable and on the expected port.
  • Check whether a compatible payload is selected.
  • Do not assume a failed exploit means the target is vulnerable or not vulnerable; module prerequisites matter.

No Session Created

  • Review the module output and payload options.
  • Confirm LHOST is an address reachable from the lab target.
  • Confirm LPORT is available and permitted by the lab network.
  • Check whether the payload architecture/platform matches the target.

Background Job Confusion

  • Run jobs to see active jobs.
  • Use jobs -k ID to stop a specific job.
  • Use sessions separately to distinguish sessions from jobs.
