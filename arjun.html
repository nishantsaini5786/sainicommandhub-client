Arjun is an HTTP parameter discovery suite. It finds hidden, undocumented query parameters on a web endpoint — parameters that aren't shown in the URL but that the server still accepts. Finding hidden params often reveals hidden functionality, debug modes, or vulnerabilities like IDOR, SSRF, and SQL injection. Made by s0md3v (same creator as XSStrike and Photon).

What is Arjun? (Deep Theory)

When you visit a URL like example.com/api/user?id=5, the server responds to two parameters: id=5. But what if the server also accepts other parameters — like admin=true, debug=1, test=1, internal=1 — that aren't in the docs?

This is called hidden parameter discovery. Arjun systematically tests thousands of common parameter names against an endpoint and identifies which ones the server actually responds to.

Why Hidden Parameters Matter

  • Hidden Functionality — Admin panels, debug modes, internal APIs
  • Authorization Bypass — Params like is_admin=true, role=admin
  • IDOR — Params like user_id=, account_id= that may not be checked
  • SSRF — Params like url=, callback=, webhook=
  • SQL Injection — Sometimes hidden params are injectable
  • XSS — Reflected params not visible in normal requests

How Arjun Works — The Smart Approach

  1. Baseline — Sends a request with no params to get baseline response
  2. Batch Testing — Sends 100-256 params at once, checks how many are reflected
  3. Binary Search — If batch found something, divides into halves to narrow down
  4. Confirmation — Tests each discovered param individually to eliminate false positives
  5. Reflection Analysis — Compares response with/without param to determine if it's processed
💡
Why it's fast: Arjun doesn't test params one by one. It batches them in groups of 100+, then uses binary search to isolate the real ones. This reduces 10,000 requests to just 50-100.

Basic Commands
1. Scan a Single URL (GET)
Send GET requests with hidden params — the most common usage.
arjun -u https://example.com/api/user
[*] Scanning: https://example.com/api/user [*] Probing the target for stability [*] Analysing HTTP response [*] Testing 25,980 parameter names [*] Found 3 parameters: id, admin, debug [+] Parameters found: id admin debug
2. POST Request Scan
For forms and APIs that use POST — params sent in body.
arjun -u https://example.com/api/login -m POST
3. JSON Body Scan
For REST APIs that accept JSON — sends {"key": "value"} format.
arjun -u https://example.com/api/user -m JSON
4. XML Body Scan
arjun -u https://example.com/api/user -m XML
5. Save Output to File
arjun -u https://example.com/api/user -oT results.txt
6. JSON Output
Machine-readable output for automation.
arjun -u https://example.com/api/user -oJ results.json
7. Scan from File (Bulk URLs)
Scan multiple URLs from a text file.
arjun -i urls.txt -oT results.txt
Advanced Scanning
8. Custom Wordlist
Use your own parameter names list for targeted discovery.
arjun -u https://example.com/api -w params.txt
9. Custom Headers
Send custom headers — useful for authenticated endpoints.
arjun -u https://example.com/api -H "Authorization: Bearer eyJhbGciOi..."
10. Multiple Custom Headers
arjun -u https://example.com/api -H "Authorization: Bearer TOKEN" -H "X-API-Key: KEY123"
11. Cookie Authentication
arjun -u https://example.com/api --cookie "session=abc123; user=admin"
12. Include Existing Params
Scan while keeping already-known params.
arjun -u "https://example.com/api?id=1"
13. Delay Between Requests
Throttle requests — avoid rate limiting / WAF blocks.
arjun -u https://example.com/api -d 2
14. Thread Control
Control concurrency — more threads = faster but noisier.
arjun -u https://example.com/api -t 20
15. Timeout Control
arjun -u https://example.com/api --timeout 15
16. Redirect Handling
arjun -u https://example.com/api --disable-redirects
Stealth & Evasion
17. Use Proxy (Burp)
Route Arjun through Burp Suite for inspection.
arjun -u https://example.com/api --proxy http://127.0.0.1:8080
18. Random User-Agent
arjun -u https://example.com/api --random-agent
19. Custom User-Agent
arjun -u https://example.com/api -H "User-Agent: Mozilla/5.0 (Windows NT 10.0)"
20. Bypass 403 Forbidden
Some endpoints return 403 to Arjun's default UA — try browser UA.
arjun -u https://example.com/api -H "User-Agent: Mozilla/5.0" --stable
Complete Workflow — Bug Bounty
Step 1: Enumerate Subdomains
Use Amass/Subfinder to find subdomains.
subfinder -d target.com -o subs.txt
Step 2: Filter Live Hosts
cat subs.txt | httpx -silent -o live.txt
Step 3: Crawl for URLs
Extract all URLs including query params.
cat live.txt | katana -silent | grep "?" | tee urls.txt
Step 4: Run Arjun
Feed URLs to Arjun for hidden param discovery.
arjun -i urls.txt -oT params.txt
Step 5: Analyze Findings
Look for interesting params: admin, debug, internal, url, callback.
Step 6: Test Params Manually
Test each param for IDOR, SSRF, SQLi, XSS using Burp.
curl "https://target.com/api?admin=true&id=1"

Troubleshooting

"No parameters found"

  • Endpoint might genuinely have no hidden params
  • Try --stable if responses are inconsistent
  • Add authentication headers if endpoint requires login
  • Try JSON mode if endpoint expects JSON: -m JSON

"Request failed / connection error"

  • Check if endpoint is alive: curl -v https://example.com/api
  • Try with --timeout 30
  • Use proxy if behind corporate firewall

"403 Forbidden on every request"

  • WAF is blocking Arjun
  • Try --random-agent
  • Route through Burp proxy to see what's blocked
  • Use custom User-Agent matching browser

"Too many false positives"

  • Increase --stable mode
  • Reduce threads: -t 1
  • Add delay: -d 1
  • Test each finding manually with curl

"Scan is very slow"

  • Increase threads: -t 20
  • Reduce wordlist size
  • Use HTTP/2 if supported
  • Run from VPS closer to target
