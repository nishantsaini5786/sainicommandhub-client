NETCAT / NCAT
NETWORK CONNECTIONS / TCP • UDP • SOCKET DEBUGGING
INTERMEDIATE60 COMMANDSNETWORKING

Netcat is a command-line networking utility for reading and writing data across network connections. On Kali, nc may refer to a Netcat implementation while Ncat is the modern Nmap Project implementation. Ncat supports TCP/UDP, IPv4/IPv6, TLS, proxying, connection brokering, access controls and other networking features. Exact flags can differ between Netcat variants, so always check nc -h or ncat --help on the installed system.

What is Netcat? (Deep Theory)

Netcat works close to the socket layer: one side can connect to a listening service, while another side can listen for incoming connections. Because stdin/stdout can be connected to a socket, it becomes useful for protocol testing, service troubleshooting, simple data transfer, lab communication and security-training exercises.

CONNECT MODE

Acts as a client and initiates a connection to a host and port.

LISTEN MODE

Acts as a simple server and waits for an incoming connection.

TCP / UDP

TCP provides a connection-oriented stream; UDP sends datagrams without the same connection semantics.

STDIN / STDOUT

Input and output can be redirected, making Netcat useful in Unix pipelines.

Netcat vs Ncat

Netcat is a family of implementations, so options vary between traditional, OpenBSD and other versions. Ncat, maintained by the Nmap Project, is a separate modern implementation with documented support for SSL/TLS, IPv6, proxying, brokering, access control and more. The official Ncat guide describes connect and listen as its two primary modes. citeturn0search0turn0search1

Installation & First Checks

On Kali, Ncat is distributed with the Nmap ecosystem. Your system may also provide a separate nc implementation. Use the package manager to inspect or install the implementation available in your repositories.

sudo apt update sudo apt install netcat-openbsd ncat command -v nc command -v ncat nc -h ncat --version

If a package name is unavailable in your configured repository, search with apt search netcat and use the implementation your lab requires.

Practical Lab Exercises

Lab 1 — TCP chat

Terminal A listens; Terminal B connects. Type text on either side to observe the byte stream.

# Terminal A ncat -l 9001 # Terminal B ncat 127.0.0.1 9001

Lab 2 — File transfer

Use only inside your own lab. The receiver redirects socket bytes to a file; the sender redirects a local file into the connection.

# Receiver ncat -l 9001 > received.txt # Sender ncat 127.0.0.1 9001 < sample.txt

Lab 3 — Raw HTTP

Connect to a web server and manually send an HTTP request. This is useful for understanding request/response boundaries and headers.

printf "GET / HTTP/1.0\r\nHost: lab.local\r\n\r\n" | ncat 192.168.56.10 80

Netcat + Nmap Workflow

Nmap is suited to discovering hosts, ports and services; Netcat/Ncat is useful afterward for manually interacting with a specific authorized service. A common lab workflow is:

01DISCOVERNmap identifies a service
02VERIFYConfirm the port is reachable
03CONNECTOpen a raw socket
04PROBESend protocol-valid data
05DOCUMENTCapture observations
nmap -sV -p 22,80,443 192.168.56.10 nc -nv 192.168.56.10 22 nc -nv 192.168.56.10 80
Key Concepts to Remember
  • Socket: an endpoint used by applications to communicate over a network.
  • Port: identifies a transport-layer endpoint associated with a service.
  • TCP: connection-oriented byte stream.
  • UDP: datagram-based transport with no TCP-style connection handshake.
  • Listener: a process waiting for incoming connections.
  • Client: a process initiating the connection.
  • Raw protocol testing: manually sending application-layer data to understand a service.
  • Implementation matters: nc flags are not identical across all Netcat variants.
