NIKTO

Nikto is an open-source web server scanner that performs comprehensive tests for potentially dangerous server and software conditions, including misconfigurations, default or insecure files, outdated software and other web-server issues. Current upstream documentation describes Nikto 2.6.1 and its CLI options, plugins, tuning, output formats and configuration files.

What is Nikto? (Deep Theory)

Nikto is a web-server scanner designed to identify known or commonly dangerous conditions. Upstream documentation describes checks for server/software misconfigurations, default and insecure files/programs, outdated software, dangerous files and other problems. It is best understood as a web-server assessment tool, not as a replacement for a full authenticated vulnerability-management platform.

WEB SERVER SCANNING

Examines HTTP/HTTPS behavior and looks for known server-side issues.

DATABASE-DRIVEN TESTS

Nikto uses test databases and plugins to decide what requests and checks to perform.

MISCONFIGURATION

Useful for finding default files, exposed resources, weak configurations and information disclosure.

REPORTING

Results can be written to text, HTML, JSON, XML, CSV and other documented formats.

Nikto is not a magic vulnerability verdict

A finding is an observation that should be validated. Version banners can be misleading, default-file checks can produce false positives, and a scanner result does not automatically prove exploitability. Treat Nikto as one stage of a broader workflow: discover → scan → validate → document → remediate → rescan.

Use only an owned lab, an authorized assessment target, or a training platform. Examples below use private lab addresses.

Installation & First Checks

On Kali, install Nikto from the Debian/Kali package repositories when it is not already present. The upstream project also documents generic Perl installation and Docker-based usage.

sudo apt update sudo apt install nikto nikto -Version nikto -Help

Scan Tuning — Understand the Categories

Nikto's tuning system can restrict testing to categories. Current documentation identifies categories including file upload, interesting files, misconfiguration/default files, information disclosure, injection, remote file retrieval, denial of service, command execution/remote shell, SQL injection, authentication bypass, software identification, remote source inclusion, web services and administrative consoles. The x mode reverses the selection.

# Example: focus on misconfiguration/default-file tests in an authorized lab nikto -h http://192.168.56.10 -Tuning 2 # Example: focus on information disclosure + software identification nikto -h http://192.168.56.10 -Tuning 3b
Nikto + Nmap + Burp Workflow

Nmap can identify hosts, ports and service versions; Nikto can then perform web-server-specific checks; an authorized proxy such as Burp Suite can help manually inspect and reproduce HTTP requests. The tools answer different questions, so their results should be correlated rather than treated as duplicates.

01NMAPFind HTTP/HTTPS ports
02NIKTOScan server-side web issues
03BURPInspect requests manually
04VALIDATEConfirm the observation
05REPORTDocument impact + fix
nmap -sV -p 80,443,8080 192.168.56.10 nikto -h http://192.168.56.10 -output nikto.json -Format json
How to Read Nikto Results

OSV / SOFTWARE

Look for server software and version information, but verify versions independently when possible.

INTERESTING FILE

A discovered file or path may expose information, backups, documentation or application behavior.

MISCONFIGURATION

Headers, methods, directory behavior or default resources may reveal hardening gaps.

FALSE POSITIVE

Reproduce the request and inspect the actual response before assigning severity.

Practical Lab Exercises
  1. Deploy a deliberately vulnerable web server in VMware/VirtualBox and record its IP.
  2. Use Nmap to identify its HTTP/HTTPS ports.
  3. Run a baseline Nikto scan and save an HTML or JSON report.
  4. Repeat with focused tuning and compare the result sets.
  5. Validate at least three findings manually with a browser or authorized proxy.
  6. Document finding → evidence → risk → remediation → verification.
  7. Harden the lab server and run Nikto again to measure the change.
Key Concepts to Remember
  • Nikto is a web-server scanner: it is strongest for server-side checks and known web-server issues.
  • Scanning is not validation: verify findings before calling them vulnerabilities.
  • Plugins + databases matter: Nikto's tests are driven by its plugin/test data architecture.
  • Output matters: save reports so findings can be reviewed and compared over time.
  • Tuning matters: focused scans can reduce noise and make a specific assessment easier to interpret.
  • Authorization matters: web scanning sends requests to a target and should only be performed within scope.
