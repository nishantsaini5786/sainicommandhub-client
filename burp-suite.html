What is Burp Suite? (Deep Theory)

When you browse a website, your browser sends HTTP requests to a server and gets responses. You normally can't see or modify these requests. Burp Suite sits between your browser and the server as a proxy — showing you every request, letting you modify it, and analyzing the responses.

How Burp Works — The Proxy Concept

  1. You configure your browser to use Burp as its proxy
  2. Burp intercepts every HTTP/HTTPS request
  3. You can view, modify, replay, or forward requests
  4. You can also fuzz parameters, scan for vulnerabilities, and analyze responses

Burp Suite Components

  • Proxy — Intercept and modify HTTP/HTTPS traffic
  • Repeater — Manually modify and resend requests
  • Intruder — Automated fuzzing and brute-forcing
  • Scanner — Automated vulnerability scanner (Pro only)
  • Decoder — Encode/decode data (base64, URL, hex)
  • Comparer — Diff two requests/responses
  • Sequencer — Analyze randomness of tokens/sessions
  • Extender — Add custom plugins (BApp Store)
  • Collaborator — Out-of-band testing (Pro only)
  • DOM Invader — Client-side testing (in browser)

Complete Workflow — Web Pentest
Step 1: Start Burp Suite
burpsuite
Step 2: Configure Browser Proxy
Set browser proxy to 127.0.0.1:8080. Or use Burp's built-in browser (Pro).
Step 3: Install CA Certificate
Visit http://burp → Download CA cert → Import to browser.
Step 4: Map the Application
Browse the target app. Burp records all endpoints in Target → Site map.
Step 5: Enable Intercept
Turn on intercept. Modify requests manually to test input validation, auth, etc.
Step 6: Test Authentication
Send login request to Repeater. Test: SQLi in username, weak passwords, MFA bypass.
Step 7: Test Authorization (IDOR)
Send request with ID to Intruder. Fuzz ID values (1-1000) to test IDOR.
Step 8: Fuzz Parameters
Send to Intruder → mark params → load payloads → attack. Look for XSS, SQLi, cmd injection.
Step 9: Check for Common Vulns
CSRF, SSRF, XXE, SSTI, deserialization, JWT issues, file upload bypasses.
Step 10: Verify Findings Manually
Use Repeater to confirm each finding. Document request/response pairs.
Step 11: Generate Report
Screenshot requests/responses. Document steps to reproduce.

Troubleshooting

"HTTPS sites show certificate errors"

  • Install Burp CA certificate: visit http://burp → Download CA
  • Import to browser's Trusted Root store
  • Firefox: about:preferences → Privacy → Certificates → View Certificates → Import

"Browser can't connect to Burp"

  • Check proxy: Burp → Proxy → Options → Proxy Listeners
  • Default: 127.0.0.1:8080
  • Some apps use custom proxy — check browser settings

"Burp freezes / slow"

  • Increase heap: java -Xmx4G -jar burpsuite.jar
  • Delete old project files
  • Disable unused extensions

"Mobile app traffic not intercepted"

  • Set Burp listener to listen on all interfaces: 0.0.0.0:8080
  • Configure phone WiFi proxy to attacker IP:8080
  • Install Burp CA on mobile (Settings → Security → Install CA)
  • Apps with SSL pinning need Frida/objection to bypass

"Intruder is slow in Community edition"

  • Community is throttled to 1 req/sec
  • Use Turbo Intruder extension for speed
  • Or upgrade to Pro for unlimited speed

"Cannot save project"

  • Temporary projects can't be saved
  • Use File → New Project → choose disk-based project
