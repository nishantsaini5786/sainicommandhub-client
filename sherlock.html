Sherlock is a command-line OSINT utility for checking whether a username appears across supported public social networks and websites. It is best used as a lead-generation and verification tool: a matching username is not, by itself, proof that every account belongs to the same person.

What is Sherlock? (Deep Theory)

Sherlock automates a repetitive OSINT task: take a candidate username and test it against a large collection of public site definitions. A result can indicate that a page exists, does not exist, or could not be checked reliably. The project documentation currently describes the command as checking usernames across social networks and supports multiple usernames in one run.

🎯
Use case: username reconnaissance, digital-footprint research, CTF/OSINT labs, brand monitoring, and authorized investigations.
⚠️
Important: username matches can be false positives. Verify the URL, profile context, activity, and independent evidence before linking an account to an identity.

How the workflow works

  1. Input: provide one or more candidate usernames.
  2. Site checks: Sherlock tests the configured public site definitions.
  3. Classification: results are reported as found/not found or may indicate errors/timeouts.
  4. Export: save results as TXT, CSV, or XLSX where supported.
  5. Verification: manually inspect the public page and collect independent evidence.
🧠
OSINT mental model: Sherlock discovers candidate locations. It does not prove ownership, identity, intent, or relationship between accounts.
Installation & First Checks

The upstream project documents pipx, pip, Docker and other package methods. On Kali, prefer a supported package/environment method rather than copying an old GitHub clone workflow.

python3 -m pip install -U sherlock-project sherlock --version sherlock --help

For an isolated pipx installation:

pipx install sherlock-project sherlock --version

Docker is another documented route:

docker run -it --rm sherlock/sherlock user123

False Positives & Verification

A username appearing on a site does not automatically establish identity. Common causes of false positives include common usernames, abandoned accounts, reused handles, site-specific placeholders, redirects, deleted pages, and changes to a site's response behavior.

1️⃣
Verify the URL: confirm the actual profile/page and not only a positive CLI status.
2️⃣
Check context: compare public bio, links, dates, profile metadata, and other non-sensitive public signals.
3️⃣
Corroborate: use at least one independent public source before treating two handles as connected.
4️⃣
Record uncertainty: distinguish confirmed observations from assumptions and failed/time-out checks.
Practical OSINT Workflow
# 1. Start with a controlled username sherlock labuser --print-found # 2. Narrow the scope if needed sherlock labuser --site github --site reddit --print-found # 3. Save evidence for your lab report sherlock labuser --csv -o report.csv # 4. Review the public pages manually

Recommended evidence format: username → site → exact public URL → date/time checked → status → notes → confidence. This keeps an OSINT report reproducible without overstating what the tool actually established.

Troubleshooting
  • Command not found: check command -v sherlock and your Python/pipx PATH.
  • Many timeouts: increase --timeout, restrict sites with --site, or inspect connectivity.
  • Unexpected positives: verify the page manually; consider site-specific false-positive behavior.
  • Outdated results: update the package/site definitions and re-run a focused check.
  • Proxy problems: validate the proxy separately and then use --proxy.
  • Debugging a site: use --verbose and, where appropriate, --dump-response.
  • Offline lab: use --local with a locally available data source; live site checks still require connectivity.
