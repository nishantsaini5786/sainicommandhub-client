HTTPX
Web Testing · Fast HTTP Toolkit for Probing & Reconnaissance
Beginner 40+ Commands Go Multi-Purpose Pipeline Friendly

HTTPx is a blazingly fast HTTP toolkit written in Go, designed for web reconnaissance, probing, and testing at scale. It takes URLs or subdomains as input and returns HTTP status codes, response headers, titles, body content, and more. HTTPx is the Swiss Army knife of HTTP investigation — perfect for bug bounty hunting, OSINT, and penetration testing workflows. One binary, infinite possibilities.

What is HTTPx? (Deep Theory)

HTTPx is not just a status code checker. It's a comprehensive HTTP client that:
• Probes HTTP/HTTPS endpoints at scale
• Extracts response metadata (title, headers, body, status, etc.)
• Chains with other tools via stdin/stdout (pipeline-friendly)
• Handles authentication, proxies, custom headers
• Filters and formats output for further analysis

Why HTTPx is Powerful

  • Speed — Concurrent probing of thousands of URLs in seconds
  • Lightweight — Single static binary, no dependencies, cross-platform
  • Feature-Rich — Status codes, titles, headers, body, tech detection, redirects
  • Pipeline-Compatible — Input from stdin, output JSON/plain text for chaining
  • Flexible Output — JSON, CSV, custom templates for easy parsing
  • Production-Ready — Used by security teams and bug bounty hunters at scale

Installation

Kali Linux (Pre-installed)

httpx -version

Install on Linux/macOS

sudo apt install -y httpx-toolkit

Install via Go (Latest)

go install -v github.com/projectdiscovery/httpx/cmd/httpx@latest

Docker

docker pull projectdiscovery/httpx:latest docker run --rm projectdiscovery/httpx:latest -u http://example.com

From Source

git clone https://github.com/projectdiscovery/httpx.git cd httpx/cmd/httpx && go build
📚
Verify Installation: httpx -version should output the version. If command not found, add $GOPATH/bin to $PATH.
Basic Usage & Common Flags
1. Single URL Probe
Get HTTP status and details for one URL.
httpx -u http://example.com
http://example.com [200] [10234]
2. Multiple URLs from List
Probe URLs from a file (one per line).
httpx -l urls.txt
3. Read from Stdin
Perfect for chaining with other tools (pipes).
cat subdomains.txt | httpx
4. Show HTTP Status Codes
Default output format.
httpx -l urls.txt -status-code
5. Extract Page Titles
Get HTML title from each page.
httpx -l urls.txt -title
6. Get Response Length
httpx -l urls.txt -length
7. Show Server Header
Identify web server technology.
httpx -l urls.txt -server
8. Extract All Headers
httpx -l urls.txt -headers
9. Combine Multiple Flags
Get status, title, server, and length in one output.
httpx -l urls.txt -status-code -title -server -length
10. Filter by Status Code
Only show URLs returning specific status codes.
httpx -l urls.txt -status-code -sc 200,301,302
11. Exclude Status Codes
httpx -l urls.txt -status-code -mc 404,500
12. Follow Redirects
Trace 301/302 chains to final destination.
httpx -l urls.txt -follow-redirects
13. Increase Threads (Speed)
Default is 150. Increase for faster scanning.
httpx -l urls.txt -threads 500
14. Custom Timeout
httpx -l urls.txt -timeout 30s
15. JSON Output
Get structured JSON for parsing/further analysis.
httpx -l urls.txt -json
16. Save to File
httpx -l urls.txt -o results.txt
17. Verbose Mode
httpx -l urls.txt -v
18. Silent Mode (No Banner)
httpx -l urls.txt -silent
19. Rate Limit (Requests/Second)
httpx -l urls.txt -rate-limit 100
20. Custom User-Agent
httpx -l urls.txt -H "User-Agent: Mozilla/5.0"
Authentication & Advanced Options
21. Basic Authentication
httpx -l urls.txt -auth "username:password"
22. Custom Header
httpx -l urls.txt -H "X-API-Key: secret123"
23. Multiple Custom Headers
httpx -l urls.txt -H "Authorization: Bearer token" -H "Accept: application/json"
24. Cookies
httpx -l urls.txt -H "Cookie: session=abc123; user=admin"
25. Use Proxy
Route traffic through proxy (Burp, etc.).
httpx -l urls.txt -proxy http://127.0.0.1:8080
26. Ignore SSL Errors
httpx -l urls.txt -insecure
27. HTTP Method (POST/PUT)
httpx -l urls.txt -method POST
28. POST Data
httpx -l urls.txt -method POST -body "username=admin&password=test"
29. Extract CSP Headers
Find Content Security Policy misconfigurations.
httpx -l urls.txt -csp
30. Detect Waf
Identify WAF/IDS/IPS based on responses.
httpx -l urls.txt -waf-detection
31. Tech Detection
Detect WordPress, Joomla, Drupal, CMS, etc.
httpx -l urls.txt -tech-detect
32. Screenshot Support (Headless Browser)
httpx -l urls.txt -screenshot
33. Extract Meta Tags
httpx -l urls.txt -extract-keywords
34. Get ASN/GeoIP Info
httpx -l urls.txt -asn
35. Custom Port Probe
Probe specific ports if not default 80/443.
httpx -l hosts.txt -ports 8080,8443,3000
Advanced Filtering & Output
36. Match Body Content
Filter URLs containing specific text in response body.
httpx -l urls.txt -mr "password" -title
37. Match Response Size
httpx -l urls.txt -msize 1000:10000
38. CSV Output
httpx -l urls.txt -csv -o results.csv
39. Output Only URLs (No Extra Info)
httpx -l urls.txt -silent | grep "200"
40. Store Response Body
Save full response for each URL.
httpx -l urls.txt -store-response -store-response-dir responses/
Real-World Workflows
Workflow 1: Subdomain Validation
subfinder -d target.com -silent | httpx -status-code -title -o live-subs.txt
Find all subdomains of target.com and filter to only live ones with HTTP status and titles.
Workflow 2: Gobuster Integration
gobuster dir -u http://target.com -w wordlist.txt -q | httpx -status-code -title -mc 404
Feed gobuster results to httpx and filter out 404s.
Workflow 3: Tech Stack Detection
httpx -l urls.txt -tech-detect -server -title -json | jq '.[] | {url: .url, tech: .tech, server: .server}'
Detect technologies and parse with jq for reporting.
Workflow 4: Status Code Hunting
httpx -l urls.txt -status-code -sc 200,401,403 -o interesting.txt
Find 200 (success), 401 (auth required), and 403 (forbidden) responses.
Workflow 5: Redirect Chain Tracing
cat urls.txt | httpx -follow-redirects -location
Follow all 301/302 redirects to see final destination.
Workflow 6: WAF Detection at Scale
httpx -l urls.txt -waf-detection -o waf-results.txt
Scan all URLs for WAF/IDS signatures.
Workflow 7: Response Body Analysis
httpx -l urls.txt -store-response -store-response-dir ./responses/ && grep -r "admin" ./responses/
Store all responses and search for specific keywords.
Workflow 8: JSON Parsing for Reports
httpx -l urls.txt -json | jq '[.[] | select(.status_code == 200)] | length'
Count total 200s with jq.

Troubleshooting

Timeout Errors / Slow Responses

  • Increase timeout: -timeout 30s
  • Reduce threads to avoid overwhelming target: -threads 50
  • Use rate-limit: -rate-limit 100

SSL Certificate Errors

  • Use -insecure flag to bypass SSL verification
  • Or use http:// instead of https://

Too Many Requests / Rate Limited (429)

  • Reduce threads: -threads 10
  • Add rate limit: -rate-limit 50
  • Add delay between requests: -delay 1000ms (if supported)

Empty or No Output

  • Check URL format (must be http://... or https://...)
  • Use -v for verbose mode to see errors
  • Test single URL first: httpx -u http://example.com

JSON Output Parsing Issues

  • Use jq for JSON parsing: httpx -l urls.txt -json | jq '.'
  • Ensure valid JSON: httpx -l urls.txt -json -o output.json

Command Not Found

  • Install: go install github.com/projectdiscovery/httpx/cmd/httpx@latest
  • Check PATH: echo $PATH | grep go
  • Add to PATH if needed: export PATH=$PATH:~/go/bin

Proxy Not Working

  • Ensure proxy is running (Burp, mitmproxy, etc.)
  • Use correct format: -proxy http://127.0.0.1:8080
  • For HTTPS through proxy, add -insecure
Pro Tips & Best Practices

Combine with Other Tools

Subfinder → HTTPx → Burp: Find live subdomains, then test in Burp Suite.

Gobuster → HTTPx → ffuf: Find directories, validate, then fuzz for bypasses.

Use JSON for Automation

Export to JSON and parse with jq, python, or jshon for reports and CI/CD pipelines.

Monitor for Changes

Run httpx regularly and diff results to detect new endpoints, status changes, or tech updates.

Combine Filters for Precision

httpx -l urls.txt -sc 200 -title -mr "admin" finds only 200s with "admin" in title.

Store Responses for Deep Analysis

Use -store-response to save full HTML, then grep or search locally.

Respect Rate Limits

Always use -rate-limit on production targets to avoid DoS accusations.
