HYDRA
Network Login Auditor · Parallel Authentication Testing
Advanced 50+ Usage Patterns C Parallelized

Hydra (THC-Hydra) is a parallelized network login auditing tool used to test authentication services against supplied username and password candidates. It supports many protocols and is useful in authorized penetration tests, CTFs, and isolated security labs.

What is Hydra? (Deep Theory)

THC-Hydra automates authentication testing against network services. Instead of manually trying credentials one by one, Hydra can coordinate many login attempts in parallel and report successful combinations.

How Hydra Works

  • Target Service — Connects to a supported authentication protocol such as SSH, FTP, HTTP form authentication, SMB, RDP, or others.
  • Username Input — Accepts a single username with -l or a username list with -L.
  • Password Input — Accepts a single password with -p or a password list with -P.
  • Parallel Attempts — Uses multiple tasks with -t to process candidates concurrently.
  • Result Reporting — Displays valid credentials when a service accepts them.

Why Hydra is Useful

  • Protocol Coverage — Supports many common network authentication services.
  • Parallelization — Multiple tasks can reduce testing time in controlled environments.
  • Flexible Inputs — Single credentials, username lists, password lists, and combinations.
  • Service-Specific Syntax — Each module can use protocol-specific options.
  • Output Options — Results can be displayed or saved for lab documentation.
  • CTF Friendly — Commonly encountered in intentionally vulnerable training machines.
💡
Key Insight: Hydra tests authentication controls; it does not magically recover a password. Its success depends on the candidate lists, protocol, rate limits, account policy, and the target service.
Real-World Use Cases

1. Authorized Penetration Testing

Assess whether exposed services accept weak or reused credentials during an approved security assessment.

2. CTF & VulnHub Labs

Test intentionally vulnerable SSH, FTP, HTTP, SMB, and other services inside a challenge environment.

3. Password Policy Auditing

Measure whether controlled test accounts resist common password candidates.

4. Service Configuration Testing

Verify that authentication services have appropriate lockout, throttling, and monitoring controls.

5. Security Training

Demonstrate how weak credentials can be discovered and why strong authentication controls matter.

Basic Usage & Core Commands

Display Hydra command-line options.
hydra -h

Check the installed Hydra version.
hydra -V
3. Single Username + Password List
Authorized lab example against an FTP service.
hydra -l testuser -P passwords.txt ftp://LAB_IP
4. Username List + Password List
Try combinations from two supplied files.
hydra -L users.txt -P passwords.txt ftp://LAB_IP
5. Single Username + Single Password
Test one known credential pair in your lab.
hydra -l testuser -p 'TestPassword123!' ssh://LAB_IP
6. SSH Authentication Test
Test an SSH service using a controlled username and wordlist.
hydra -l testuser -P passwords.txt ssh://LAB_IP
7. FTP Authentication Test
Test an FTP login service in an authorized lab.
hydra -l testuser -P passwords.txt ftp://LAB_IP
8. SMB Authentication Test
Use the SMB module against a lab host.
hydra -l testuser -P passwords.txt smb://LAB_IP
9. RDP Authentication Test
Test RDP credentials only on an authorized training system.

Increase or decrease concurrent login attempts.

11. Stop After First Valid Credential
Stop once Hydra finds a valid login.
hydra -l testuser -P passwords.txt -f ssh://LAB_IP
12. Verbose Output
Show more details while the lab test is running.
hydra -l testuser -P passwords.txt -vV ssh://LAB_IP
13. Save Results to a File
Write discovered results to a local report file.

14. Specify a Custom Port
Test a service running on a non-default port.
hydra -l testuser -P passwords.txt -s 2222 ssh://LAB_IP
15. Username and Password Lists with SSH
Combine both list inputs for an authorized SSH lab.
hydra -L users.txt -P passwords.txt ssh://LAB_IP
16. Check a Module's Syntax
Display protocol-specific options.
hydra -U ssh
17. FTP Module Help
Display FTP-specific module information.
hydra -U ftp
18. HTTP Form Module Help
Display the HTTP form module syntax before building a lab test.
hydra -U http-post-form
19. HTTP Basic Authentication
Test HTTP Basic Auth on a controlled web application.
hydra -l testuser -P passwords.txt LAB_IP http-get /protected/
20. HTTP POST Form (Lab Example)
Use the form module only when you understand the application's login response.
hydra -l testuser -P passwords.txt LAB_IP http-post-form "/login:user=^USER^&pass=^PASS^:F=Invalid credentials"
21. HTTPS Form Module
Use HTTPS form testing against an authorized application.
hydra -l testuser -P passwords.txt LAB_IP https-post-form "/login:user=^USER^&pass=^PASS^:F=Invalid"
22. Use a Delay Between Attempts
Slow the testing rate when a lab service needs lower request pressure.
hydra -l testuser -P passwords.txt -W 2 ssh://LAB_IP
23. Quiet Mode
Reduce non-essential console output.
hydra -l testuser -P passwords.txt -q ssh://LAB_IP
24. Debug Output
Use debug information when troubleshooting a lab module.
hydra -l testuser -P passwords.txt -d ssh://LAB_IP
25. IPv6 Target
Test an IPv6 lab host when the selected module supports it.
hydra -l testuser -P passwords.txt ssh://[LAB_IPV6]
26. Username File + Fixed Password
Test several controlled accounts against one known test password.
hydra -L users.txt -p 'TestPassword123!' ssh://LAB_IP
27. Fixed Username + Password File
Common lab pattern for one test account.
hydra -l testuser -P passwords.txt ftp://LAB_IP
28. Use a Larger Task Count Carefully
Increase concurrency only when the authorized service and lab network can handle it.
hydra -l testuser -P passwords.txt -t 8 ssh://LAB_IP
29. Combine Verbose + Save Output
Useful when documenting a lab exercise.
hydra -l testuser -P passwords.txt -vV -o hydra-report.txt ftp://LAB_IP
30. Stop After First Result + Save
Stop after the first valid result and record it locally.
hydra -L users.txt -P passwords.txt -f -o first-result.txt ssh://LAB_IP

Real-World Lab Workflows
Workflow 1: CTF SSH Authentication Lab
nmap -p 22 LAB_IP hydra -l testuser -P passwords.txt -t 4 ssh://LAB_IP ssh testuser@LAB_IP
Discover SSH → test the supplied lab account → verify the result.
Workflow 2: FTP Lab
nmap -p 21 -sV LAB_IP hydra -l testuser -P passwords.txt ftp://LAB_IP ftp LAB_IP
Identify FTP → test the authorized account → validate access manually.
Workflow 3: HTTP Login Form Lab
curl -i http://LAB_IP/login hydra -l testuser -P passwords.txt LAB_IP http-post-form "/login:user=^USER^&pass=^PASS^:F=Invalid credentials"
Understand the request and failure response first, then test only the lab application.
Workflow 4: Rate-Limit Validation
hydra -l testuser -P passwords.txt -t 1 -W 3 ssh://LAB_IP
Use low concurrency to observe how the service handles repeated authentication failures.
Workflow 5: Documenting a Lab Result
hydra -l testuser -P passwords.txt -vV -o hydra-report.txt ssh://LAB_IP cat hydra-report.txt
Run the test → save output → include the result in your authorized lab notes.
Troubleshooting & Common Issues

Connection Refused

  • Confirm the service is actually listening with nmap -p PORT LAB_IP.
  • Check the VM network mode and firewall rules in your lab.

Module Error

  • Check module-specific syntax with hydra -U module.
  • Verify the protocol and port are correct.

No Valid Credentials Found

  • Verify the username/password lists are correct for the lab.
  • Confirm the login failure condition for HTTP forms.
  • Check whether the account is locked or rate-limited.

Too Many Connections

  • Reduce concurrency with -t 1 or -t 2.
  • Increase the wait interval with -W where appropriate.

HTTP Form Test Fails

  • Inspect the form with browser developer tools or curl.
  • Confirm the POST path, parameter names, and failure string.
  • Check whether the application uses CSRF tokens or dynamic fields that require a different testing approach.

Results Not Saved

  • Use an absolute or writable output path with -o.
  • Check permissions in the current directory.

AUTHORIZED USE ONLY. Hydra performs repeated authentication attempts. Use it only on systems, accounts, and applications you own or have explicit permission to test.

Legal / Safe Use:
✅ Your own systems and test accounts
✅ CTF competitions and VulnHub/THM-style labs
✅ Authorized penetration tests with written scope
✅ Isolated security research environments

Avoid:
❌ Testing public services without permission
❌ Guessing credentials for third-party accounts
❌ Attempting to bypass rate limits on systems you do not control
