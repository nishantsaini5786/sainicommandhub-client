DNSRECON
Information Gathering · DNS Enumeration Tool
Intermediate 25+ Commands DNS Recon Zone Transfer Subdomain Enum

DNSRecon is a powerful DNS enumeration and reconnaissance tool written in Python. It's a standard part of Kali Linux and is used by penetration testers and bug bounty hunters to discover DNS records, subdomains, mail servers, name servers, and even attempt zone transfers. If you're doing external recon, DNSRecon is essential.

What is DNSRecon? (Deep Theory)

DNS is the "phone book" of the internet — it translates domain names (like example.com) into IP addresses. But DNS also contains a wealth of information about an organization: mail servers, name servers, subdomains, IP addresses, and more.

DNSRecon queries DNS servers to extract this information systematically.

What DNSRecon Discovers

  • A records — IPv4 addresses
  • AAAA records — IPv6 addresses
  • MX records — Mail servers (email infrastructure)
  • NS records — Name servers (who controls DNS)
  • TXT records — SPF, DKIM, DMARC, verification tokens
  • CNAME records — Aliases (reveals third-party services)
  • SOA records — Zone authority info
  • SRV records — Services (VoIP, LDAP, etc.)
  • PTR records — Reverse DNS lookups
  • Subdomains — via wordlist brute-force
  • Zone Transfers — if misconfigured (huge win!)
  • Wildcard detection — identifies catch-all DNS

Why DNS Reconnaissance Matters

  • Attack surface mapping — find all external-facing systems
  • Subdomain takeover — find abandoned subdomains
  • Email spoofing — check SPF/DKIM/DMARC misconfigs
  • Third-party services — CNAME records reveal SaaS, cloud services
  • Internal IP leaks — misconfigured DNS may expose internal IPs
  • Zone transfer — reveals entire DNS zone (rare but critical)
💡
Zone transfer explained: DNS servers normally only answer specific queries. But if misconfigured, they'll hand over the entire zone file — all subdomains, IPs, and records. This is a goldmine for pentesters and a critical misconfiguration.
Real-World Use Cases

1. Bug Bounty Recon

First step in any bug bounty. Find subdomains, IPs, and infrastructure before testing.

2. Penetration Testing

External recon phase — map the target's attack surface, find mail servers, name servers, and hidden subdomains.

3. Subdomain Takeover Hunting

Find subdomains pointing to decommissioned third-party services (Heroku, GitHub Pages, AWS S3) — potential takeover.

4. Email Security Audit

Check SPF, DKIM, DMARC records — misconfigurations allow email spoofing.

5. Red Team Reconnaissance

Before attacking, map the full target infrastructure without touching a single server.

6. Threat Intelligence

Analyze DNS of suspicious domains — find related infrastructure, hosting providers, etc.

7. Compliance / Audit

Verify DNS configuration of your own domains — check for missing records, wildcards, etc.

8. CTF / Learning

DNS-based CTF challenges often need zone transfer, TXT record analysis, or subdomain enumeration.

Basic Commands
1. Standard DNS Enumeration
Perform all standard DNS record lookups (A, AAAA, MX, NS, TXT, SOA).
dnsrecon -d example.com
[*] Performing General Enumeration of Domain: example.com [-] DNSSEC is not configured for example.com [*] SOA ns1.example.com 192.0.2.1 [*] NS ns1.example.com 192.0.2.1 [*] NS ns2.example.com 192.0.2.2 [*] MX 10 mail.example.com 192.0.2.10 [*] A example.com 93.184.216.34 [*] TXT example.com v=spf1 include:_spf.example.com ~all [*] TXT example.com google-site-verification=xxxxx
2. Save Output to JSON
dnsrecon -d example.com -j output.json
3. Save to CSV
dnsrecon -d example.com -c output.csv
4. Save to XML
dnsrecon -d example.com -x output.xml
5. Use Specific Name Server
Query a specific DNS server instead of the default.
dnsrecon -d example.com -n 8.8.8.8
6. Verbose Output
dnsrecon -d example.com -v
Zone Transfer Commands
7. Attempt Zone Transfer ⚠ AUTHORIZED ONLY
Tries AXFR zone transfer from all NS records of the domain. Huge win if successful.
dnsrecon -d example.com -t axfr
[*] Attempting Zone Transfer against ns1.example.com [+] Zone Transfer was successful!! admin.example.com 192.0.2.5 dev.example.com 192.0.2.15 staging.example.com 192.0.2.20 mail.example.com 192.0.2.10 vpn.example.com 192.0.2.30
8. Zone Transfer to File ⚠ AUTHORIZED ONLY
dnsrecon -d example.com -t axfr -j axfr.json
9. Zone Transfer with Specific NS ⚠ AUTHORIZED ONLY
dnsrecon -d example.com -t axfr -n ns1.example.com
Subdomain Enumeration
10. Subdomain Brute-Force
Try words from a wordlist as subdomains.
dnsrecon -d example.com -t brt -D /usr/share/wordlists/dnsmap.txt
[*] Performing host and subdomain brute force against example.com [+] www.example.com 93.184.216.34 [+] mail.example.com 93.184.216.35 [+] dev.example.com 93.184.216.40 [+] admin.example.com 93.184.216.50 [+] api.example.com 93.184.216.60
11. Custom Wordlist
dnsrecon -d example.com -t brt -D /path/to/custom-wordlist.txt
12. Brute-Force with Big Wordlist
dnsrecon -d example.com -t brt -D /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
13. Brute-Force with Threads
Speed up scanning with more threads.
dnsrecon -d example.com -t brt -D wordlist.txt --threads 20
14. Include Wildcard Result
Include wildcard subdomains in results (default skips them).
dnsrecon -d example.com -t brt -D wordlist.txt -w
Reverse Lookup & PTR
15. Reverse Lookup (PTR)
Find hostnames for a given IP range.
dnsrecon -r 192.0.2.0/24
[*] Performing Reverse Lookup from 192.0.2.0 to 192.0.2.255 [+] PTR 192.0.2.1 ns1.example.com [+] PTR 192.0.2.10 mail.example.com [+] PTR 192.0.2.34 www.example.com
16. Reverse Lookup Range
dnsrecon -r 192.0.2.1-192.0.2.100
17. PTR Lookup with Specific NS
dnsrecon -r 192.0.2.0/24 -n 8.8.8.8
SRV Records & Advanced
18. SRV Record Enumeration
Find services like SIP, LDAP, Kerberos via SRV records.
dnsrecon -d example.com -t srv
[*] Performing Service Record Enumeration [+] _sip._tcp.example.com 10 60 5060 sip.example.com [+] _ldap._tcp.example.com 10 60 389 ldap.example.com [+] _kerberos._tcp.example.com 10 60 88 krb.example.com
19. SPF Record Check
Extract and analyze SPF records — check for email spoofing risk.
dnsrecon -d example.com -t spf
20. Google Enumeration
Use Google to find subdomains and info (deprecated but useful).
dnsrecon -d example.com -t goo
21. Cache Snooping
Check what's in DNS cache of a resolver.
dnsrecon -t snoop -n 8.8.8.8 -D wordlist.txt
22. TLD Expansion
Try common TLDs for a domain name.
dnsrecon -d example.com -t tld
23. Zone Walking (DNSSEC NSEC)
Enumerate DNSSEC NSEC records to find subdomains.
dnsrecon -d example.com -t zonewalk
24. WhoIs Lookup
dnsrecon -d example.com -t whois
25. DNSSEC Validation
dnsrecon -d example.com -t dnssec
Complete Workflow — Bug Bounty Recon
Step 1: Standard Enumeration
dnsrecon -d target.com -j recon-1.json
Step 2: Attempt Zone Transfer
dnsrecon -d target.com -t axfr -j recon-2.json
If successful, you've found a critical misconfiguration.
Step 3: Subdomain Brute-Force
dnsrecon -d target.com -t brt -D /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -j recon-3.json
Step 4: SRV Record Enumeration
dnsrecon -d target.com -t srv
Step 5: SPF/DMARC Check
Look for misconfigured email security.
dnsrecon -d target.com -t spf
Step 6: Reverse Lookup on Found IPs
Find more hosts by PTR lookups on discovered IP ranges.
dnsrecon -r 192.0.2.0/24
Step 7: Consolidate Results
Merge all JSON outputs into a single file.
Step 8: Test Discovered Hosts
Use nmap, httpx, or nuclei against discovered subdomains.

Troubleshooting

"Zone transfer failed"

  • Zone transfer usually fails — most servers block it (correctly)
  • Try against each NS individually: -n ns1.example.com
  • Only succeeds on misconfigured servers

"Brute-force takes forever"

  • Use smaller wordlist first (dnsmap.txt)
  • Increase threads: --threads 30
  • Use faster resolver: -n 8.8.8.8

"Wildcard detected, no results"

  • Server returns same IP for any subdomain
  • DNSRecon auto-detects and skips
  • Use -w to see wildcard results

"No SPF record found"

  • Domain might not use SPF — that's a finding in itself
  • Check TXT record manually: dig TXT example.com

"Connection refused / no response"

  • DNS server might be unreachable
  • Try a public resolver: -n 1.1.1.1
  • Check network connectivity

"Reverse lookup returns nothing"

  • PTR records often not configured for IP ranges
  • Try smaller ranges
  • Use faster resolver for large ranges

AUTHORIZED USE ONLY. DNSRecon queries DNS servers, attempts zone transfers, and brute-forces subdomains. Only use:
• Against domains you own
• In authorized penetration tests (signed contract)
• In bug bounty programs (within scope)
• For security research on your own assets

Unauthorized DNS enumeration may violate the CFAA, Computer Misuse Act, and similar laws. Especially zone transfer attempts can be flagged as attacks. Always get written authorization before testing external domains.
