Masscan is a high-speed asynchronous TCP port scanner designed for large-scale port discovery. Its syntax is intentionally similar to Nmap, but its design focuses on quickly discovering open ports across many hosts rather than performing deep single-host enumeration. The official project describes it as an Internet-scale port scanner and notes that its own TCP/IP stack requires care with local networking and banner checks.

What is Masscan? (Deep Theory)

Masscan is built around asynchronous packet transmission. Instead of waiting for each target to complete before moving to the next one, it can transmit probes at a configured rate and process replies as they arrive. This makes it particularly useful for the first phase of large authorized network surveys: quickly answering “Which hosts appear to have this port open?”

Masscan vs Nmap

Nmap is generally stronger when you need deep enumeration of an individual host: service/version detection, NSE scripts, OS detection and detailed protocol interaction. Masscan focuses on breadth and speed. A common authorized workflow is therefore Masscan for discovery → Nmap for focused enumeration.

How Masscan Works

  1. Target selection: provide an IP, range, CIDR block, IPv6 range, or target file.
  2. Port selection: specify TCP ports with -p/--ports; UDP ports can be prefixed with U:.
  3. Rate control: choose a packet transmission rate appropriate for your lab/network.
  4. Asynchronous probing: Masscan sends probes and handles responses without using the same workflow as a traditional sequential scanner.
  5. Result processing: findings can be printed or saved as list, JSON/NDJSON, XML, grepable, binary or other supported output formats.
💡
Key Insight: Masscan is not simply “a faster Nmap.” It makes different engineering trade-offs. Use it to discover open ports quickly, then use a deeper tool when you need service-specific enumeration.
Installation & First Checks

Install on Kali Linux

sudo apt update && sudo apt install -y masscan

Check Version

masscan --version

Show Help

masscan --help

List Interfaces and Routes

sudo masscan --iflist

For your Kali lab, replace TARGET with a machine or subnet that you own or are explicitly authorized to scan. Start with a low rate such as 100–1000 packets/second and increase only when the environment can safely handle it.

Masscan Command Library — 50+ Commands

Every command below is written as a learning template. TARGET means an authorized IP/host/range. The examples intentionally use conservative rates rather than Internet-wide scanning.

1. Basic TCP Port Scan
Scan an authorized lab target for one TCP port.
sudo masscan TARGET -p80 --rate 1000
2. Multiple TCP Ports
Scan a small, explicit TCP port set.
sudo masscan TARGET -p22,80,443 --rate 1000
3. Port Range
Scan a contiguous TCP port range.
sudo masscan TARGET -p1-1000 --rate 1000
4. Common Web Ports
Quickly check common web service ports on a lab target.
sudo masscan TARGET -p80,443,8080,8443 --rate 1000
5. Full TCP Port Range
Check all TCP ports on a controlled target. Use a conservative rate in labs.
sudo masscan TARGET -p0-65535 --rate 1000
6. CIDR Target
Scan an authorized private lab subnet using CIDR notation.
sudo masscan 192.168.1.0/24 -p80,443 --rate 1000
7. IP Range Target
Scan an explicit IP range in an authorized environment.
sudo masscan 192.168.1.10-192.168.1.50 -p22,80 --rate 1000
8. Multiple Targets
Supply more than one authorized target range.
sudo masscan 192.168.1.10 192.168.1.20 192.168.1.30 -p80 --rate 1000
9. Named Ports Option
Use the long form of the port option for readability.
sudo masscan TARGET --ports 22,80,443 --rate 1000
10. UDP Port
Scan a UDP port by prefixing the port with U:.
sudo masscan TARGET --ports U:53 --rate 500
11. UDP Range
Scan a controlled UDP port range.
sudo masscan TARGET --ports U:53,U:161,U:500-510 --rate 500
12. TCP + UDP
Combine TCP and UDP port specifications.
sudo masscan TARGET --ports 80,443,U:53 --rate 500
13. Banner Grabbing
Request supported application banners from an authorized service.
sudo masscan TARGET -p80 --banners --rate 100
14. Banner + Web Ports
Attempt limited banner collection from common web ports.
sudo masscan TARGET -p80,443,8080 --banners --rate 100
15. Set Packet Rate
Control packets transmitted per second; start low in labs.
sudo masscan TARGET -p80 --rate 1000
16. Set Maximum Rate
Use the current option name for a transmission ceiling.
sudo masscan TARGET -p80 --max-rate 1000
17. Choose Interface
Select the network interface Masscan should use.
sudo masscan TARGET -p80 --adapter eth0 --rate 1000
18. Short Interface Option
Use -e as the short form for the adapter/interface.
sudo masscan TARGET -p80 -e eth0 --rate 1000
19. List Interfaces
Display interfaces and routes Masscan can use for troubleshooting.
sudo masscan --iflist
20. Open Results Only
Display only open or possibly-open ports.
sudo masscan TARGET -p22,80,443 --open --rate 1000
21. Verbose Output
Increase console verbosity while troubleshooting a scan.
sudo masscan TARGET -p80 --rate 1000 -v
22. More Verbose Output
Increase verbosity further when investigating behavior.
sudo masscan TARGET -p80 --rate 1000 -vv
23. Debug Output
Enable additional debugging information.
sudo masscan TARGET -p80 --rate 1000 -d
24. Packet Trace
Show packets sent and received for troubleshooting a lab scan.
sudo masscan TARGET -p80 --packet-trace --rate 100
25. List Output
Save results in Masscan list format.
sudo masscan TARGET -p22,80,443 --rate 1000 -oL masscan.txt
26. JSON Output
Save results as JSON for scripts and later parsing.
sudo masscan TARGET -p22,80,443 --rate 1000 -oJ masscan.json
27. NDJSON Output
Write newline-delimited JSON output for streaming/parsing workflows.
sudo masscan TARGET -p22,80,443 --rate 1000 -oD masscan.ndjson
28. XML Output
Save results in XML format for structured tooling.
sudo masscan TARGET -p22,80,443 --rate 1000 -oX masscan.xml
29. Grepable Output
Save results in grepable output format.
sudo masscan TARGET -p22,80,443 --rate 1000 -oG masscan.gnmap
30. Binary Output
Save binary results, useful for Masscan-specific workflows and resume operations.
sudo masscan TARGET -p22,80,443 --rate 1000 -oB masscan.bin
31. Append Output
Append new results instead of replacing an existing output file.
sudo masscan TARGET -p80 --rate 1000 -oL masscan.txt --append-output
32. Flush Output
Flush output as hosts are found so another process can read results in near real time.
sudo masscan TARGET -p80 --rate 1000 -oL masscan.txt --output-flush
33. Exclude One IP
Explicitly prevent a specific authorized-scope exception from being scanned.
sudo masscan 192.168.1.0/24 --exclude 192.168.1.10 -p80 --rate 1000
34. Exclude a Range
Exclude a subnet or range from the scan target set.
sudo masscan 192.168.1.0/24 --exclude 192.168.1.20-192.168.1.30 -p80 --rate 1000
35. Exclude File
Load multiple exclusions from a file.
sudo masscan 192.168.1.0/24 --excludefile exclude.txt -p80 --rate 1000
36. Include File
Read authorized target ranges from a file.
sudo masscan --includefile targets.txt -p80,443 --rate 1000
37. Retries
Send a defined number of retries when packet loss is expected.
sudo masscan TARGET -p80 --retries 2 --rate 500
38. Wait After Scan
Wait briefly after transmitting so late responses can be collected.
sudo masscan TARGET -p80 --wait 5 --rate 1000
39. Configuration Echo
Generate a configuration representation instead of immediately running the scan.
sudo masscan TARGET -p80 --rate 1000 --echo > scan.conf
40. Run Config File
Run a previously prepared Masscan configuration file.
sudo masscan -c scan.conf
41. Resume Scan
Resume an interrupted scan using saved Masscan state/configuration.
sudo masscan --resume paused.conf
42. Configuration With Output
Create a reusable configuration containing rate, ports, range, and output settings.
sudo masscan TARGET -p80,443 --rate 1000 -oX scan.xml --echo > scan.conf
43. HTTP User-Agent
Set a custom HTTP User-Agent for supported banner interactions in an authorized lab.
sudo masscan TARGET -p80 --banners --http-user-agent 'SAINICOMMANDHUB-Lab' --rate 100
44. Custom Hello String
Provide a protocol hello string for supported banner workflows.
sudo masscan TARGET -p80 --banners --hello-string 'GET / HTTP/1.0\r\n\r\n' --rate 100
45. Custom Hello File
Read a banner hello payload from a file.
sudo masscan TARGET -p80 --banners --hello-file hello.txt --rate 100
46. IPv6 Target
Scan an explicitly authorized IPv6 lab target/range.
sudo masscan 2001:db8::10 -p80 --rate 500
47. Source Port
Set the source port used by Masscan's packet generation in a controlled lab setup.
sudo masscan TARGET -p80 --source-port 61000 --rate 500
48. Source IP
Select a source IP address in a controlled network setup where you are authorized to configure it.
sudo masscan TARGET -p80 --source-ip 192.168.1.50 --rate 500
49. Router MAC
Explicitly specify the gateway/router MAC when automatic discovery is unsuitable.
sudo masscan TARGET -p80 --router-mac AA:BB:CC:DD:EE:FF --rate 500
50. Custom Source MAC
Specify the adapter/source MAC for an authorized low-level lab setup.
sudo masscan TARGET -p80 --adapter-mac AA:BB:CC:DD:EE:FF --rate 500
51. Scan With Open Filter + JSON
Keep only open findings and save them in JSON for automation.
sudo masscan TARGET -p22,80,443 --open --rate 1000 -oJ open.json
Masscan Workflow — Discovery to Enumeration
Define Scope
Write down the exact IPs/subnets that are authorized. Create an exclusion file for systems that must never be touched.
Choose a Small Port Set
Start with ports relevant to the exercise, such as 22, 80 and 443, instead of immediately scanning every port.
Set a Conservative Rate
Begin around 100–1000 packets/second in a normal lab and observe packet loss, router load and target behavior.
Save Structured Output
Use JSON or XML when the result will be processed later. Use list/grepable output for simple command-line workflows.
Validate Findings
A Masscan result is a discovery signal. Confirm important findings with a slower, service-aware scanner such as Nmap.
Enumerate the Service
Once open ports are known, perform focused service/version enumeration against only those authorized hosts and ports.

Output Formats & Automation

Masscan supports several output styles. JSON/NDJSON are convenient when another script will parse the results; XML can fit workflows that already consume Nmap-like structured data; list and grepable formats are easy to inspect from a shell.

JSON → Quick Review

cat masscan.json | less

Extract Open Ports From List Output

grep -i 'open' masscan.txt

Use Results for Focused Nmap Enumeration

nmap -sC -sV -p PORTS TARGET
🔗
Practical pattern: Masscan answers “where are the open ports?” while Nmap can answer “what service/version is running there and what further enumeration is useful?” Keep the second-stage scan limited to confirmed, authorized targets.
Rate, Reliability & Network Behavior

Masscan's most important operational parameter is its packet rate. The official project documentation emphasizes that the program can generate traffic extremely quickly. A rate that is reasonable for one lab can be disruptive on another network, especially when virtualization, Wi-Fi, routing equipment, IDS/IPS, or low-powered targets are involved.

Why Start Low?

  • Packet loss: sending faster than the path can handle can reduce the quality of results.
  • Target load: a very fast scan can create a noticeable burst of traffic.
  • Virtual labs: VMware/VirtualBox networking can behave differently from bare metal.
  • Wi-Fi: wireless networks generally need more conservative rates than a controlled wired lab.
  • Detection: high-rate scanning is noisy and can trigger IDS/IPS alerts.
⚠
RATE WARNING: Never copy a high-speed Internet-scale rate into an environment you do not own or have explicit authorization to test. Masscan can generate traffic much faster than a normal manual scan. Use a low rate first and increase only when the scope and network capacity are known.
Troubleshooting

“No Results”

  • Confirm the target is reachable and actually has the selected port listening.
  • Check that you selected the correct interface with --iflist / -e.
  • Try a lower rate to reduce packet loss.
  • Compare with a focused Nmap scan against the same authorized host.

Wrong Interface / Route

  • Run sudo masscan --iflist.
  • Select the intended interface explicitly with -e eth0 or your lab interface.

Banner Scanning Causes Problems

Masscan uses its own TCP/IP stack. The official project notes that banner checks can interact with the operating system's network stack, so source-port/IP and local firewall configuration may matter in advanced setups. For ordinary port discovery, keep the workflow simple and use Nmap or another service-aware tool for deeper protocol enumeration.

Too Many False Negatives

  • Reduce --rate.
  • Increase --retries when appropriate.
  • Use --wait to allow late responses.
  • Verify the route, interface and target firewall behavior.

Need to Continue Later?

Use Masscan configuration/state features such as --echo, -c and --resume so repeatable scans do not depend on manually reconstructing every option.
