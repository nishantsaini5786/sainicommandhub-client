Subfinder is a fast passive subdomain enumeration tool from ProjectDiscovery. It queries configured passive online sources, normalizes findings and supports clean stdout, files and JSONL output for recon pipelines. Its core purpose is discovery rather than active exploitation.

What is Subfinder? (Deep Theory)

Subdomain enumeration is the process of discovering hostnames belonging to a parent domain, such as api.example.com, dev.example.com or mail.example.com. Subfinder is designed primarily for passive discovery, meaning it gathers names from external sources instead of directly brute-forcing DNS names.

Core Concepts

  • Passive enumeration: obtain hostnames from public datasets and provider APIs.
  • Source: an individual provider that can contribute candidate subdomains.
  • Recursive source: a source capable of discovering deeper names such as a.b.example.com.
  • Wildcard elimination: helps reduce false discoveries caused by wildcard DNS.
  • Active mode: optional resolution-oriented filtering for live/resolvable subdomains.
  • Provider configuration: API keys and provider settings live in Subfinder's provider configuration.
  • JSONL: newline-delimited JSON is useful when source attribution needs to be preserved.

Mental Model

DOMAIN → PASSIVE SOURCES → NORMALIZE / FILTER → SUBDOMAINS → OPTIONAL RESOLUTION → HTTP / DNS / PORT ENUMERATION

💡
Important: Subfinder is primarily a passive discovery tool. A hostname appearing in results does not automatically mean the host is live, owned by the intended organization, or vulnerable. Validate findings before drawing conclusions.

Source & Provider Architecture

Subfinder's architecture is modular: each passive source can contribute candidate names. Free/public sources can work without credentials, while API-backed providers may need keys in the provider configuration. Using -s is useful when you want a controlled source set; -all broadens collection but can be slower and may consume provider quotas.

subfinder -ls subfinder -d example.com -s crtsh,github subfinder -d example.com -all

Troubleshooting

Few or no results

  • Check that the domain is spelled correctly.
  • Run subfinder -ls to confirm available sources.
  • Review provider configuration and API-key requirements.
  • Compare a selected-source run with -all.
  • Remember that passive coverage is never guaranteed to be complete.

Provider errors / rate limits

Reduce request rates with -rl, use provider-specific limits with -rls, and avoid repeatedly hammering the same APIs. API quotas and source policies can change independently of Subfinder.

Pipeline looks messy

Use -silent when another command expects only hostnames. Save JSONL separately when you need source metadata.

Subfinder + Other Recon Tools
# Passive discovery subfinder -d example.com -silent -o subs.txt # DNS validation cat subs.txt | dnsx -silent -o resolved.txt # HTTP validation cat resolved.txt | httpx -silent -status-code -title -o live.txt # Keep an evidence copy tee subfinder-run.txt < subs.txt

This separation is useful because Subfinder answers “what hostnames are known?”, while DNS/HTTP tools answer different validation questions.

Learning Checklist
  • Understand passive vs active enumeration.
  • Know the difference between -s and -all.
  • Understand why API keys affect source coverage.
  • Use -silent for clean pipelines.
  • Use JSONL + -cs when source attribution matters.
  • Know when recursive enumeration is appropriate.
  • Respect provider quotas and API terms.
  • Validate discovered hosts before deeper testing.
