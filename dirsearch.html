DIRSEARCH
Web Security · Web Path Scanner
Beginner 25+ Commands Directory Brute Recursive Multi-threaded

Dirsearch is a fast, multi-threaded web path scanner written in Python. It brute-forces directories, files, and extensions on web servers to discover hidden admin panels, backup files, configuration files, and sensitive endpoints. If a website has a /admin panel that isn't linked anywhere — Dirsearch will find it.

What is Dirsearch? (Deep Theory)

Most websites hide interesting endpoints that aren't linked in menus:

  • /admin — admin panel
  • /backup.zip — backup archive
  • /.env — environment variables with DB creds
  • /config.php.bak — source code backup
  • /api/v1/users — undocumented API endpoint
  • /phpinfo.php — server info leak
  • /.git/ — exposed git repo

Dirsearch tries thousands of common paths and filenames to discover these hidden resources.

How Dirsearch Works

  1. Loads a wordlist of common paths (dirs, files, extensions)
  2. Sends HTTP requests to http://target/WORD
  3. Analyzes response codes — 200 (found), 403 (exists but forbidden), 301 (redirect)
  4. Filters out "soft 404s" (custom error pages) by comparing response sizes
  5. Recursively scans discovered directories
  6. Reports interesting findings

Response Codes to Watch

CodeMeaningAction
200FoundInvestigate immediately
301/302RedirectFollow redirect, may reveal more
401Auth requiredTry common credentials
403Forbidden (but exists!)Try bypass techniques
500Server errorMight crash with different input

Why Dirsearch is Powerful

  • Fast — multi-threaded, 30+ requests/sec
  • Smart filtering — detects and skips soft 404s
  • Recursive — auto-scans found directories
  • Extensive wordlists — included with Seclists-quality lists
  • Multi-extension — tests .php, .html, .bak, .zip, .txt simultaneously

Basic Commands
1. Basic Directory Scan
Scan a URL with default wordlist and extensions.
dirsearch -u http://target.com
Target: http://target.com/ [10:30:15] Starting: [10:30:16] 200 - 12KB - /index.html [10:30:16] 200 - 15KB - /about.html [10:30:18] 301 - 0B - /admin -> /admin/ [10:30:20] 403 - 300B - /.htaccess [10:30:22] 200 - 5KB - /robots.txt [10:30:25] 200 - 25KB - /backup.zip [10:30:30] 200 - 15KB - /config.php.bak
2. Scan with Custom Extensions
Force specific file extensions.
dirsearch -u http://target.com -e php,html,js,txt,zip,bak
3. Use Custom Wordlist
dirsearch -u http://target.com -w /usr/share/wordlists/dirb/common.txt
4. Use SecLists Big Wordlist
dirsearch -u http://target.com -w /usr/share/seclists/Discovery/Web-Content/raft-large-directories.txt
5. Recursive Scan
Auto-scan discovered directories.
dirsearch -u http://target.com -r
6. Depth Control
Limit recursion depth.
dirsearch -u http://target.com -r -R 3
7. Increase Threads
Faster scan but more aggressive.
dirsearch -u http://target.com -t 50
8. Slow Scan (Avoid Detection)
dirsearch -u http://target.com -t 5 --delay 1
Filtering & Response Handling
9. Show Only Specific Status Codes
Only show 200 responses.
dirsearch -u http://target.com --include-status 200
10. Show Multiple Status Codes
dirsearch -u http://target.com --include-status 200,301,302,403
11. Hide Specific Status Codes
dirsearch -u http://target.com --exclude-status 404,500
12. Exclude Response Sizes
Filter out soft 404s by response size.
dirsearch -u http://target.com --exclude-sizes 0B,300B,1024B
13. Exclude by Regex
dirsearch -u http://target.com --exclude-texts "Not Found"
14. Exclude by Redirect
dirsearch -u http://target.com --exclude-redirect "http://target.com/home"
15. Include Response Length
dirsearch -u http://target.com --include-status 200 -l
HTTP Configuration
16. Custom User-Agent
dirsearch -u http://target.com --user-agent "Mozilla/5.0 (X11; Linux x86_64)"
17. Custom Cookie
For authenticated scans.
dirsearch -u http://target.com --cookie "session=abc123; user=admin"
18. Custom Header
dirsearch -u http://target.com -H "Authorization: Bearer token123"
19. HTTP Basic Auth
dirsearch -u http://target.com --http-method GET --auth-type basic --auth admin:password
20. Use Proxy (Burp)
dirsearch -u http://target.com --proxy http://127.0.0.1:8080
21. Follow Redirects
dirsearch -u http://target.com --follow-redirects
22. Ignore SSL Errors
dirsearch -u https://target.com --skip-on-status 500 --no-check-certificate
23. POST Requests Instead of GET
dirsearch -u http://target.com --http-method POST --data "id=FUZZ"
24. Random User-Agents
dirsearch -u http://target.com --random-agent
Output & Reporting
25. Save Output
dirsearch -u http://target.com -o output.txt
26. JSON Report
dirsearch -u http://target.com --format json -o report.json
27. HTML Report
dirsearch -u http://target.com --format html -o report.html
28. XML Report
dirsearch -u http://target.com --format xml -o report.xml
29. Scan Multiple URLs from File
dirsearch -l urls.txt
30. Multiple URLs in One Command
dirsearch -u http://target1.com,http://target2.com
Complete Workflow — Bug Bounty Recon
Step 1: Quick Scan First
dirsearch -u http://target.com -e php,html,js,txt,bak,zip -t 25
Step 2: Analyze Findings
Look for: /admin, /.git, /.env, /backup.zip, /config.php.bak, /phpinfo.php
Step 3: Deep Scan with Big Wordlist
dirsearch -u http://target.com -w /usr/share/seclists/Discovery/Web-Content/raft-large-directories.txt -e php,html,js -r -R 2
Step 4: Filter Out Noise
dirsearch -u http://target.com --exclude-status 404,500 --exclude-sizes 0B
Step 5: Save Report
dirsearch -u http://target.com -o report.json --format json
Step 6: Manual Testing
Open interesting paths in browser. Test /admin for weak creds, /.git for source code, /.env for DB creds.
Step 7: Chain with Other Tools
Feed found URLs to Burp, Nuclei, or XSStrike for further testing.

Troubleshooting

"Too many 404s / soft 404 detected"

  • Custom error pages return 200 — Dirsearch auto-detects
  • Manually exclude: --exclude-sizes 1234B
  • Exclude by text: --exclude-texts "Not Found"

"Rate limited / 429"

  • Reduce threads: -t 5
  • Add delay: --delay 1
  • Use proxy rotation
  • Random User-Agent: --random-agent

"WAF blocks requests"

  • Slow down: -t 3 --delay 2
  • Custom UA matching browser
  • Use Burp proxy + ZAP
  • Try --random-agent

"Scan is very slow"

  • Increase threads: -t 50
  • Use smaller wordlist
  • Reduce extensions: -e php
  • Skip recursion: remove -r

"False positives"

  • Enable smart 404 detection: --exclude-sizes
  • Verify manually with curl
  • Use --random-agent to avoid cache-based false positives

"No results at all"

  • Check target is reachable: curl -I http://target.com
  • Try HTTPS: -u https://target.com
  • Skip SSL: --no-check-certificate
  • Check WAF blocking: use Burp proxy
⚠
AUTHORIZED USE ONLY. Dirsearch brute-forces paths on web servers — thousands of requests per minute. This is illegal against systems you don't own. Only use:
• On your own websites
• In authorized penetration tests (signed contract)
• In bug bounty programs (within scope)
• For learning on CTF platforms

Unauthorized web scanning may violate the CFAA, Computer Misuse Act, IT Act, and similar laws. Even a single non-authorized request to a protected system can be a crime. Always get written authorization first.
