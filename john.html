John the Ripper is an offline password-security auditing tool that tests password hashes against candidate passwords and cracking modes. It is widely used for authorized security labs, CTFs, password-audit exercises, and forensic workflows.

What is John the Ripper? (Deep Theory)

John the Ripper (JtR) is designed to help security professionals evaluate password strength from password hashes. It works offline: the tool receives hashes, generates password candidates, applies transformations or attack modes, hashes those candidates, and compares the results with the supplied hashes.

How John Works

  1. Obtain password hashes from an authorized lab or audit source.
  2. Identify or auto-detect the hash format where possible.
  3. Choose a cracking mode such as wordlist, single, incremental, or mask.
  4. John generates candidates and compares their hashes against the target hash set.
  5. Recovered passwords can be displayed with --show.

Why It Is Useful

  • Password auditing: identify weak passwords in controlled environments.
  • CTF/lab work: recover intentionally vulnerable credentials.
  • Format testing: work with many password-hash formats and protected files.
  • Rule-based testing: apply common password mutations to wordlists.
💡
Key Insight: John does not magically decrypt every password hash. Success depends on the hash format, candidate quality, attack mode, password complexity, available hardware, and configuration.

John the Ripper Commands
1. Show Help
Display John command-line options.
john --help
2. Show Version
Check the installed John version.
john --version
3. List Supported Formats
Display hash formats supported by the installed build.
john --list=formats
4. Basic Wordlist Attack
Test a hash file against a supplied password wordlist in an authorized lab.
john --wordlist=passwords.txt hashes.txt
5. Wordlist With a Specific Format
Explicitly tell John which hash format to use when the format is known.
john --format=FORMAT --wordlist=passwords.txt hashes.txt
6. Show Cracked Passwords
Display credentials John has already recovered for the loaded hash file.
john --show hashes.txt
7. Single Crack Mode
Generate candidates from account information and test them.
john --single hashes.txt
8. Incremental Mode
Use John's incremental/brute-force style candidate generation in a controlled lab.
john --incremental hashes.txt
9. Mask Mode
Generate candidates matching a defined character pattern.
john --mask='?d?d?d?d' hashes.txt
10. Apply Rules to a Wordlist
Apply John word mangling rules to candidate words.
john --wordlist=passwords.txt --rules hashes.txt
11. Use a Named Rule Set
Select a specific rules section from the John configuration.
john --wordlist=passwords.txt --rules=Wordlist hashes.txt
12. Check Current Status
Display progress, speed, and current cracking status.
john --status
13. Restore an Interrupted Session
Resume a John session after stopping it.
john --restore
14. Create a Named Session
Give a cracking job a session name for easier resume/status control.
john --session=lab01 --wordlist=passwords.txt hashes.txt
15. Restore a Named Session
Resume a previously named John session.
john --restore=lab01
16. List Sessions
View available session information on the local system.
john --status=lab01
17. Benchmark John
Measure cracking performance on the local machine.
john --test
18. Benchmark a Format
Benchmark a particular hash format when supported.
john --test --format=FORMAT
19. Show Cracked Passwords for a Format
Display recovered entries while explicitly selecting the format.
john --format=FORMAT --show hashes.txt
20. Generate Candidates Only
Use John's candidate-generation mode for inspecting attack behavior.
john --wordlist=passwords.txt --stdout
21. Wordlist With Custom Rules and Candidate Output
Inspect transformed candidates before using them in an audit.
john --wordlist=passwords.txt --rules --stdout
22. Convert Linux Password Files
Combine authorized passwd/shadow files into a John-readable input.
unshadow passwd.txt shadow.txt > hashes.txt
23. Extract Hashes From a ZIP Archive
Create a John-compatible hash from an authorized protected ZIP file.
zip2john protected.zip > zip_hash.txt
24. Extract Hashes From a RAR Archive
Prepare an authorized protected RAR archive for offline password auditing.
rar2john protected.rar > rar_hash.txt
25. Extract Hashes From an SSH Private Key
Prepare an authorized encrypted SSH key for offline password auditing.
ssh2john id_rsa > ssh_hash.txt
26. Extract a PDF Password Hash
Prepare an authorized password-protected PDF for offline auditing.
pdf2john protected.pdf > pdf_hash.txt
27. Extract a KeePass Hash
Prepare an authorized KeePass database for offline password auditing.
keepass2john vault.kdbx > keepass_hash.txt
28. Use a Custom Pot File
Store recovered passwords in a separate local pot file for an isolated project.
john --pot=lab.pot --wordlist=passwords.txt hashes.txt
29. Force a Known Format
Use this when automatic format detection is ambiguous and you know the correct format.
john --format=FORMAT hashes.txt
30. Combine Format and Rules
Run a rule-based wordlist audit against a known hash format.
john --format=FORMAT --wordlist=passwords.txt --rules hashes.txt

Troubleshooting & Common Issues

Hash Format Not Recognized

  • Check the input file for accidental spaces, line breaks, or missing fields.
  • Use john --list=formats and explicitly specify the known format.

No Passwords Recovered

  • Try a better wordlist or authorized candidate set.
  • Check whether the password is likely outside the chosen attack mode.
  • Confirm the hash format is correct.

Very Slow Performance

  • Use john --test to benchmark the local build.
  • Choose a focused wordlist/rule set instead of unnecessarily broad candidate generation.

Session Interrupted

  • Use john --status to inspect a running job.
  • Use john --restore or a named session to continue.

Archive Converter Missing

  • Check whether the relevant *2john utility is installed and available in your PATH.
  • Use the converter that matches the exact file format.
