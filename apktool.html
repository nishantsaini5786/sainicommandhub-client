Apktool is a reverse engineering tool for Android APK files. It decodes the binary resources and DEX bytecode into near-original form, allowing you to inspect, modify, and rebuild Android applications. It's a must-have for mobile security researchers, malware analysts, and CTF players.

What is Apktool? (Deep Theory)

Android apps ship as APK files (Android Package Kit). An APK is essentially a ZIP archive containing compiled code and resources. Here's what's inside:

  • classes.dex — Dalvik Executable — compiled Java/Kotlin bytecode
  • AndroidManifest.xml — Binary XML declaring permissions, activities, services
  • res/ — Compiled resources (layouts, strings, images)
  • resources.arsc — Binary resource index
  • lib/ — Native libraries (.so files)
  • META-INF/ — Signature files (CERT.RSA, MANIFEST.MF)
  • assets/ — Raw asset files

The Problem

You can't just unzip an APK and read the code. The DEX is bytecode (like .class files), the XML is binary, and the resources are compiled. Apktool solves this — it reverses everything into human-readable form.

What Apktool Does

  • Decodes DEX → Smali (assembly-like, human-readable)
  • Decodes binary XML → plain XML
  • Decodes resources.arsc → readable strings and layouts
  • Rebuilds modified files back into a working APK
  • Signs the rebuilt APK for testing

Smali — The Intermediate Language

When Apktool decodes an APK, Java/Kotlin code becomes Smali — a human-readable assembly for the Dalvik VM. It's not Java, but it's close enough to understand and modify. Example:

.method public isPremium()Z .locals 1 const/4 v0, 0x0 return v0 .end method

This returns false always. Change 0x0 to 0x1, rebuild, sign — premium unlocked! That's the power of Apktool.

💡
Note: Apktool is a decoder + rebuilder, not a full decompiler. For Java source code, use jadx. Apktool + jadx is the ultimate combo — jadx for reading, Apktool for editing.
Real-World Use Cases

1. Mobile App Security Auditing

Pentesters decode APKs to inspect permissions, hardcoded secrets, insecure API keys, and improper data storage.

2. Malware Analysis

Android malware analysts decode malicious APKs to understand behavior — C2 servers, data exfiltration, permission abuse.

3. CTF Challenges

Android CTF challenges often hide flags in Smali code, resources, or native libraries. Apktool reveals them.

4. App Modding & Patching

Modders patch APKs — unlock premium features, remove ads, bypass root detection, disable SSL pinning for testing.

5. Removing Certificate Pinning

Security researchers patch apps to disable SSL pinning so they can intercept traffic with Burp Suite.

6. Localization & Rebranding

Companies modify APK strings, icons, and resources to create white-label versions.

7. Privacy Analysis

Decode apps to see what data they collect, which trackers they use, and how they handle user data.

Basic Decoding Commands
1. Decode APK (Standard)
Extracts and decodes APK to a folder with same name as file.
apktool d app.apk
I: Using Apktool 2.9.3 on app.apk I: Loading resource table... I: Decoding AndroidManifest.xml with resources... I: Loading resource table from file... I: Regular manifest package... I: Decoding file-resources... I: Decoding values */* XMLs... I: Baksmaling classes.dex... I: Copying assets and libs... I: Copying unknown files... I: Copying original files...
2. Decode to Custom Directory
apktool d app.apk -o my_output_folder
3. Force Decode (Overwrite Existing)
If output folder exists, overwrite without prompting.
apktool d -f app.apk
4. Decode Without Source (Resources Only)
Skip DEX decoding — faster, only resources and manifest.
apktool d -s app.apk
5. Decode Without Resources (Smali Only)
Only DEX → Smali. Skip resource decoding.
apktool d -r app.apk
6. Decode with Debug Info
Preserve line numbers for debugging.
apktool d -d app.apk
Rebuilding Commands
7. Rebuild APK
Package modified folder back into APK.
apktool b app_folder
I: Using Apktool 2.9.3 I: Checking whether sources has changed... I: Smaling smali folder into classes.dex... I: Checking whether resources has changed... I: Building resources... I: Copying libs... I: Building apk file... I: Copying unknown files/dir... I: Built apk into: app_folder/dist/app.apk
8. Rebuild with Custom Output
apktool b app_folder -o modified.apk
9. Force Rebuild
apktool b -f app_folder
10. Rebuild with Debug Info
apktool b -d app_folder
📝
Important: After rebuilding, the APK is unsigned. Android will refuse to install it. You must sign it (next section).
Signing the Rebuilt APK
11. Generate Keystore (One Time)
Create your signing key.
keytool -genkey -v -keystore mykey.keystore -alias mykey -keyalg RSA -keysize 2048 -validity 10000
12. Sign APK with apksigner (Modern)
Android's official signing tool.
apksigner sign --ks mykey.keystore --ks-key-alias mykey modified.apk
13. Sign APK with jarsigner (Legacy)
jarsigner -verbose -keystore mykey.keystore modified.apk mykey
14. Zipalign (Optimize)
Align APK for better runtime performance.
zipalign -v 4 modified.apk final.apk
15. Verify Signature
apksigner verify final.apk
Frameworks & Resources
16. Install Framework
Install framework-res.apk from a ROM/device for system app decoding.
apktool if framework-res.apk
17. List Installed Frameworks
apktool list-frameworks
18. Empty Framework Directory
Clear cached frameworks if decode fails.
apktool empty-framework-dir
Advanced Commands
19. Decode a Specific DEX File
If APK has multiple DEX files (multidex), decode all.
apktool d app.apk --only-main-classes
20. Decode Using Specific API Level
Some APKs need a specific Android API for correct decoding.
apktool d -p framework-res.apk app.apk
21. Change App Version (Smali)
After decoding, edit apktool.yml to change version.
nano app_folder/apktool.yml
22. Modify AndroidManifest.xml
After decode, manifest is plain XML — add permissions, activities, etc.
nano app_folder/AndroidManifest.xml
23. Patch Root Detection ⚠ AUTHORIZED TESTING ONLY
Find isRooted method in Smali and force it to return false.
grep -r "isRooted" app_folder/smali/
24. Patch SSL Pinning ⚠ AUTHORIZED TESTING ONLY
Look for CertificatePinner in Smali and disable it.
grep -r "CertificatePinner" app_folder/smali/
25. Extract Native Libraries
APK's .so files are in lib/ folder — analyze with Ghidra/IDA.
ls app_folder/lib/
26. Extract Strings for Analysis
strings app_folder/classes.dex | grep -i "api\|key\|secret\|password"
Complete Workflow — Patch & Rebuild
Step 1: Decode the APK
apktool d target.apk
Step 2: Locate the Target Code
Search Smali folder for method to patch.
grep -r "isPremium" target/smali/
Step 3: Edit the Smali File
Open in editor, modify return value.
nano target/smali/com/example/App.smali
Step 4: Rebuild the APK
apktool b target -o patched.apk
Step 5: Zipalign
zipalign -v 4 patched.apk patched-aligned.apk
Step 6: Sign
apksigner sign --ks mykey.keystore --ks-key-alias mykey patched-aligned.apk
Step 7: Install & Test
adb install patched-aligned.apk

Troubleshooting

"brut.androlib.exception" during decode

  • Framework mismatch — try apktool if framework-res.apk
  • Clear cached frameworks: apktool empty-framework-dir
  • Update Apktool: sudo apt install --only-upgrade apktool

"Rebuild fails with resource errors"

  • Decode with --only-main-classes to skip problematic files
  • Try apktool b -f folder
  • Check apktool.yml for version mismatches

"App crashes after rebuild"

  • Ensure signature is valid: apksigner verify app.apk
  • Check that zipalign was run
  • Some apps use signature verification — need to patch

"APK won't install"

  • Uninstall original first (signature mismatch)
  • Enable "Unknown sources"
  • Signature check: adb install -r patched.apk

"Smali code is unreadable"

  • Use jadx alongside Apktool for Java view
  • Smali is assembly-like, not Java — takes practice
  • Check original file naming pattern (a.smali, b.smali = obfuscated)
