WhatWeb is a web technology fingerprinting tool. It identifies technologies such as CMS platforms, web servers, JavaScript libraries and other components by matching responses against plugins. The current upstream release is 0.6.4. citeturn0search0turn0search1

What is WhatWeb? (Deep Theory)

WhatWeb answers a simple reconnaissance question: “What is that Website?” It is primarily a fingerprinting tool, not a general-purpose vulnerability scanner. Its plugin system can use strings, regular expressions, hashes, URL recognition, HTML patterns and other matching logic to identify technologies. citeturn0search0turn0search2

Core workflow

TARGET → REQUEST → RESPONSE → PLUGIN MATCH → TECHNOLOGY FINGERPRINT → VALIDATION

Aggression levels

  • 1 — Stealthy: one HTTP request per target and redirects.
  • 3 — Aggressive: additional requests when level-1 matches indicate they may help.
  • 4 — Heavy: many requests and aggressive tests from plugins.
💡
Important: A fingerprint is evidence, not proof of a vulnerability. Validate important technology/version findings with additional authorized evidence.
Installation & First Check
sudo apt update sudo apt install whatweb whatweb --version whatweb --help

On Kali, WhatWeb is commonly available from the distribution packages. Always check the installed version before documenting a lab result.

80 WhatWeb Commands

All examples below are intended for systems you own or are explicitly authorized to assess.

1. Basic scan
Fingerprint a single website.
whatweb https://example.com
2. Scan multiple targets
Scan more than one authorized URL in a single command.
whatweb https://example.com https://example.org
3. Verbose scan
Show additional plugin descriptions in the output.
whatweb -v https://example.com
4. Extra verbose
Increase verbosity another level when you need more detail.
whatweb -vv https://example.com
5. Aggression level 1
Default/stealthy mode; one HTTP request per target plus redirects.
whatweb -a 1 https://example.com
6. Aggression level 3
Run additional requests when level-1 matches justify them.
whatweb -a 3 https://example.com
7. Aggression level 4
Heavy fingerprinting; useful in a controlled lab when more requests are acceptable.
whatweb -a 4 https://example.com
8. Read targets from file
Scan URLs/hostnames stored in a text file.
whatweb -i targets.txt
9. Pipe targets from stdin
Feed a list directly into WhatWeb.
cat targets.txt | whatweb -i /dev/stdin
10. List plugins
Display the installed plugin list.
whatweb -l
11. Plugin information
Display detailed information about a selected plugin.
whatweb -I WordPress
12. Search plugins
Search plugin names/descriptions for a keyword.
whatweb --search-plugins wordpress
13. Select plugins
Run only the specified plugin(s).
whatweb -p WordPress https://example.com
14. Combine plugins
Run multiple selected plugins.
whatweb -p WordPress,Apache https://example.com
15. Plugin grep
Show only results matching text/regex.
whatweb --grep "WordPress" https://example.com
16. Plugin dorks
Display Google dorks associated with a selected plugin when available.
whatweb --dorks WordPress
17. Custom User-Agent
Send a custom HTTP User-Agent.
whatweb -U "Mozilla/5.0" https://example.com
18. Custom header
Add an HTTP request header.
whatweb -H "X-Test: SAINI" https://example.com
19. Multiple headers
Supply more than one header for a controlled test.
whatweb -H "X-Test: SAINI" -H "Accept: application/json" https://example.com
20. Basic authentication
Provide HTTP Basic authentication credentials to an authorized application.
whatweb -u "user:password" https://example.com
21. Cookies
Send cookies with the request.
whatweb -c "session=VALUE" https://example.com
22. Cookie jar
Read/save cookies through a cookie-jar file.
whatweb --cookie-jar cookies.txt https://example.com
23. Disable cookies
Turn off automatic cookie handling.
whatweb --no-cookies https://example.com
24. Follow redirects
Control redirect behavior.
whatweb --follow-redirect always https://example.com
25. Never follow redirects
Keep the scan on the original response.
whatweb --follow-redirect never https://example.com
26. Limit redirects
Set the maximum number of contiguous redirects.
whatweb --max-redirects 5 https://example.com
27. HTTP proxy
Send traffic through an HTTP proxy.
whatweb --proxy 127.0.0.1:8080 https://example.com
28. Proxy authentication
Authenticate to a configured proxy.
whatweb --proxy 127.0.0.1:8080 --proxy-user user:password https://example.com
29. URL prefix
Prepend a URL scheme/path to targets.
whatweb --url-prefix https:// 192.168.1.20
30. URL suffix
Append a path to each target.
whatweb --url-suffix /robots.txt https://example.com
31. URL pattern
Insert each input target into a URL pattern.
whatweb -i hosts.txt --url-pattern "https://%insert%/robots.txt"
32. Scan CIDR range
Fingerprint web services across an authorized IP range.
whatweb 192.168.1.0/24
33. Suppress errors
Hide error messages during a large controlled scan.
whatweb --no-errors 192.168.1.0/24
34. HTTPS prefix for range
Add HTTPS to IP-range targets.
whatweb --no-errors --url-prefix https:// 192.168.1.0/24
35. Set thread count
Control simultaneous requests.
whatweb -t 10 https://example.com
36. Open timeout
Set the connection-open timeout in seconds.
whatweb --open-timeout 10 https://example.com
37. Read timeout
Set the response read timeout.
whatweb --read-timeout 20 https://example.com
38. Wait between connections
Add a delay between connections; useful when using a single thread.
whatweb --wait 2 -t 1 https://example.com
39. Output sync
Flush output immediately for real-time monitoring.
whatweb --output-sync https://example.com
40. Output buffer size
Manually set the output buffer size.
whatweb --output-buffer-size 4096 https://example.com
41. Version
Display the installed WhatWeb version.
whatweb --version
42. Short help
Show concise command-line help.
whatweb --short-help
43. Full help
Show complete command-line usage.
whatweb --help
44. Debug mode
Raise plugin errors for troubleshooting.
whatweb --debug https://example.com
45. Save brief output
Write a compact result log to a file.
whatweb --log-brief=whatweb.txt https://example.com
46. Save verbose object output
Store object-oriented result data in a log format supported by the installation.

47. MongoDB logging
Send results to a configured MongoDB logging backend.
whatweb --log-mongo-host 127.0.0.1:27017 https://example.com
48. Elasticsearch logging
Send results to a configured Elasticsearch backend.
whatweb --log-elastic-host 127.0.0.1:9200 https://example.com
49. Combine file + verbosity
Read many targets while retaining useful plugin detail.

50. Combine proxy + headers
Observe requests through a local interception proxy.
whatweb --proxy 127.0.0.1:8080 -H "X-Lab: true" https://lab.local
51. WordPress fingerprint
Use the WordPress plugin for a focused identification check.
whatweb -p WordPress https://lab.local

54. Nginx fingerprint
Check for Nginx-related fingerprints.

55. Scan an internal lab host
Fingerprint a web service by IP in your own lab.

56. Scan a specific path
Fingerprint a known application path.

57. Robots file check
Combine URL suffix with plugin matching for robots.txt.
whatweb --url-suffix /robots.txt -p robots_txt https://example.com
58. Crossdomain check
Check for a crossdomain.xml file using the corresponding plugin.
whatweb --url-suffix /crossdomain.xml -p crossdomain_xml https://example.com
59. Batch + no errors
Useful for larger authorized target lists.
whatweb -i targets.txt --no-errors
60. Batch + threads
Process a target file with controlled concurrency.

61. Batch + timeout
Prevent slow hosts from holding up the scan indefinitely.

62. Compare aggression levels
Run the same lab target with different request depth.

63. Enumerate plugins then select
Find a plugin name before using it.
whatweb -l | grep -i wordpress whatweb -p WordPress https://lab.local
64. Inspect a plugin
Search for a plugin and then view its details.
whatweb -I=WordPress
65. Search plugin keyword
Find plugins related to a technology.
whatweb --search-plugins apache
66. Filter output with regex
Keep only matching result text.
whatweb --grep "/WordPress|Drupal|Joomla/" https://lab.local
67. Custom lab header
Use a harmless marker to identify your authorized test traffic.
whatweb -H "X-Security-Lab: SAINI" https://lab.local

Identify your assessment traffic at the application layer.
whatweb -U "SAINI-SECURITY-LAB" https://lab.local
69. Through Burp proxy
Inspect WhatWeb requests in Burp during a lab assessment.
whatweb --proxy 127.0.0.1:8080 https://lab.local
70. Troubleshoot a plugin
Enable debug output when a plugin causes an error.
whatweb --debug -p PluginName https://lab.local
71. Check version before work
Record the installed tool version for reproducibility.
whatweb --version
72. Full local workflow
Start with low-noise fingerprinting, then increase depth if needed.
whatweb -a 1 https://lab.local whatweb -v https://lab.local whatweb -a 3 https://lab.local
73. Nmap to WhatWeb workflow
Use Nmap to identify web ports, then fingerprint the discovered HTTP service.
nmap -sV -p 80,443 192.168.56.101 whatweb http://192.168.56.101
74. WhatWeb to Burp workflow
Fingerprint first, then inspect the application manually through an intercepting proxy.
whatweb https://lab.local whatweb --proxy 127.0.0.1:8080 https://lab.local
75. Range + HTTPS workflow
Apply an HTTPS prefix to a controlled network range.
whatweb --no-errors --url-prefix https:// 192.168.56.0/24
76. File + URL pattern
Build a repeatable path-based fingerprinting workflow from a target list.
whatweb -i hosts.txt --url-pattern "https://%insert%/robots.txt"
77. Slow controlled scan
Reduce concurrency and add delay for a fragile lab service.
whatweb -t 1 --wait 2 --open-timeout 10 --read-timeout 20 https://lab.local
78. Fast controlled batch
Increase concurrency only when the lab can handle it.
whatweb -i targets.txt -t 25 --no-errors
79. Plugin-focused lab scan
Use only a known technology plugin to reduce unrelated output.
whatweb -p WordPress https://lab.local
80. Final verification scan
Repeat a low-aggression scan after changes to compare fingerprints.
whatweb -a 1 -v https://lab.local

Practical Recon Workflow
  1. Start with whatweb -a 1 target.
  2. Record server/CMS/framework fingerprints.
  3. Use -v when more plugin context is needed.
  4. Use -a 3 only when additional requests are acceptable.
  5. Validate interesting versions with Nmap, HTTP headers, application behavior or vendor documentation.
  6. Move to dedicated tools such as WPScan or Nikto only when the technology and scope justify it.
Troubleshooting
  • No output: verify the URL, DNS and connectivity.
  • Too many requests: reduce aggression and thread count.
  • Slow target: tune open/read timeouts.
  • Proxy issues: verify the proxy listener and address.
  • Plugin error: reproduce with --debug.
  • Unexpected fingerprint: treat it as a lead and manually validate it.
