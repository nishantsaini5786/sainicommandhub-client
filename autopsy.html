Autopsy is the world's leading open-source digital forensics platform. It's a graphical interface for The Sleuth Kit (TSK) and other forensic tools. Autopsy lets investigators analyze disk images, recover deleted files, extract artifacts, and build timelines — all through a user-friendly GUI. Used by law enforcement, incident responders, and forensic analysts worldwide.

What is Autopsy? (Deep Theory)

When a cybercrime occurs, investigators need to analyze the suspect's computer — but they can't just turn it on (evidence could be modified). Instead, they make a forensic image (bit-for-bit copy) of the disk, then analyze that image with tools like Autopsy.

What Autopsy Does

  • Reads disk images — E01, DD, RAW, VHD, VMDK, etc.
  • Recovers deleted files — from unallocated space
  • Extracts metadata — timestamps, EXIF, MFT records
  • Parses artifacts — browser history, USB devices, registry
  • Extracts keywords — searches images for text matches
  • Builds timeline — activity timeline of events
  • Hashes files — MD5/SHA256 for verification
  • Generates reports — HTML, PDF, Excel, CSV

Autopsy vs The Sleuth Kit

  • TSK — Command-line tools (fls, icat, mmls, etc.)
  • Autopsy — GUI frontend for TSK + additional modules
  • Best Practice: Autopsy for interactive analysis, TSK for automation

Autopsy Modules (Plugins)

  • Recent Activity — browser history, downloads, cookies
  • Hash Lookup — check against NSRL, known bad files
  • File Type Identification — magic bytes vs extension
  • Extension Mismatch — detect renamed malware
  • EXIF Parser — GPS, camera, timestamps from images
  • Keyword Search — Indexed search across disk
  • Email Parser — PST, MBOX, EML files
  • Web Artifacts — Chrome/Firefox/Safari/Edge
  • Timeline — chronological activity analysis
  • Registry — Windows registry hives parsing
  • Android Analyzer — extract from Android images
  • PhotoRec Carver — recover photos from raw data

Getting Started — CLI Launch
1. Launch Autopsy GUI
Start the graphical interface (opens in browser on newer versions).
autopsy
Autopsy starting... Opening browser at http://localhost:8080/autopsy/
2. Launch on Custom Port
autopsy -p 9999
3. Launch with Custom Case Directory
autopsy -d /path/to/cases
4. Check Java Version
java -version
5. Memory Settings
Increase heap memory for large disk images.
JAVA_OPTS="-Xmx8G" autopsy
Workflow — Analyzing a Disk Image
Step 1: Create New Case
Open Autopsy → Click "New Case" → Enter case name, examiner name, case directory.
Step 2: Add Data Source
Choose image type: Disk Image, Local Disk, Logical Files, or Android image.
Step 3: Select Image File
Browse to your .E01, .dd, .raw, or .img file. Autopsy auto-detects format.
Step 4: Configure Ingest Modules
Enable modules you want: Recent Activity, Hash Lookup, File Type ID, EXIF Parser, Keyword Search, Timeline.
Step 5: Wait for Ingest
Autopsy processes the image. Time depends on disk size and modules enabled. Can take hours for large disks.
Step 6: Browse Results
Left panel shows: Data Sources → Views (File Types, Deleted Files, Keyword Hits) → Results.
Step 7: Analyze & Tag
Mark interesting files with Tags (Follow Up, Notable Item, etc.). Add comments.
Step 8: Generate Report
Tools → Generate Report → Choose format: HTML, PDF, XLS, CSV.

Companion CLI Tools (The Sleuth Kit)

Autopsy is GUI — but you can also use TSK command-line tools for scripting and automation.

1. fls — List Files
List files and directories in disk image.
fls -r -o 2048 disk.img
2. icat — Extract File by Inode
Extract file from image using inode number.
icat -o 2048 disk.img 12345 > extracted.txt
3. mmls — Partition Table
Show partition layout of disk image.
mmls disk.img
GUID Partition Table (EFI) Offset Sector: 0 Units are in 512-byte sectors Slot Start End Length Description 00: Meta 0000000000 0000000000 0000000001 Safety Table 01: Meta 0000000001 0000000001 0000000001 GPT Header 02: 000 0000002048 0000500735 0000498688 EFI system partition 03: 001 0000500736 0050000000 0049499264 Microsoft basic data
4. istat — Inode Info
Show metadata for a specific inode.
istat -o 2048 disk.img 12345
5. fsstat — File System Info
fsstat -o 2048 disk.img
6. blkcat — Block Content
Extract content of a specific block.
blkcat -o 2048 disk.img 12345
7. tsk_recover — Bulk Recover
Recover all files from disk image to output folder.
tsk_recover -o 2048 disk.img recovered_files/
8. hfind — Hash Lookup
Look up hash in NSRL database.
hfind /usr/share/nsrl/nsrl.db 5d41402abc4b2a76b9719d911017c592
9. sorter — File Classification
Sort files by type (images, executables, docs).
sorter -d output_dir -h -sha256 disk.img
10. mactime — Timeline
Build activity timeline from bodyfile.
fls -r -m / disk.img > bodyfile.txt && mactime -b bodyfile.txt -d > timeline.csv
Creating Forensic Images

Before analyzing, you need a forensic image. Common tools:

1. dd — Basic Imaging

sudo dd if=/dev/sdb of=disk.img bs=4M status=progress

2. dcfldd — Enhanced dd

sudo dcfldd if=/dev/sdb of=disk.img hash=sha256 hashwindow=1G

3. ddrescue — Damaged Drives

sudo ddrescue /dev/sdb disk.img disk.log

4. Guymager — GUI Imaging

sudo guymager
🛡️
Best Practice: Always work on a copy (image), never the original. Use write blockers when imaging physical drives. Verify hash (MD5/SHA256) before and after.

Troubleshooting

"Autopsy won't start / Java error"

  • Check Java: java -version (needs Java 8 or 11)
  • Install: sudo apt install openjdk-11-jdk
  • Unsupported Java: Autopsy doesn't work with Java 17+ yet

"Ingest is very slow"

  • Disable unused modules (Hash Lookup is slowest)
  • Increase heap memory: JAVA_OPTS="-Xmx8G" autopsy
  • Use SSD for case directory

"Image won't load"

  • Check file integrity: md5sum image.E01
  • Split E01 files — all parts must be in same folder
  • Try different format (DD/RAW usually works universally)

"Autopsy crashes on large images"

  • Increase heap: -Xmx16G
  • Process one partition at a time
  • Use CLI tools (fls, icat) for targeted analysis

"Deleted files not found"

  • Not all deleted files are recoverable
  • Check "Deleted Files" view in Autopsy
  • Try file carving with PhotoRec or Foremost for raw recovery
